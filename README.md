# PlanCheck

선택형 AI 문맥 분석은 기본 비활성인 Vercel Preview 실험입니다. 서버 환경변수·선택 전송 범위·비용 제한·합성 자료 평가 방법은 [Preview 실험 안내](docs/ai-preview.md)를 참고하세요. [실제 실패 진단](docs/ai-context-failure-diagnosis.md)에서 표기 대조 개선과 남은 오탐·엔진 연결 한계를 구분했습니다. API 키 없이 기존 규칙 기반 검사를 사용할 수 있습니다.

Excel 재무표와 Word 보고서를 등록하면 숫자 차이와 계획의 확인 후보를 자동으로 찾는 재무설계 문서 검사기입니다. 자동 발견과 사용자 확인 후 확정 검증을 구분하며, CALC·CROSS·ALLOC·PLAN 엔진을 재사용합니다. 자동 재무상담이나 재무설계 생성은 수행하지 않습니다.

## 실행

Node.js 22.12 이상을 사용합니다.

```sh
npm ci
npm run dev
npm test
npm run build
npm run lint
npm run format:check
```

PowerShell 실행 정책으로 npm.ps1이 차단되면 `npm.cmd`를 사용합니다.

코드 서식은 `.prettierrc`로 관리합니다. 작은따옴표, 들여쓰기 2칸, 줄 너비 140을 사용하며 `npm run format`으로 정리합니다. 원본 금융 문서와 비공개 검사 산출물은 서식 처리에서도 제외합니다.

## 사용

빠른 검토 흐름은 다음과 같습니다. 기존 원시 데이터·고급 계산·계획 편집 기능도 유지합니다.

1. ‘검사 시작’에서 XLSX와 DOCX를 선택하고 ‘검사 시작’을 누릅니다. 데이터 확인이나 규칙 설정을 먼저 할 필요가 없습니다. 원본 요약·셀·문단·표는 기본적으로 접혀 있습니다.
2. ‘검사 결과’는 우선 확인할 문제 / 추가 확인 / 상세 분석 기록으로 구분합니다. 기본 화면은 핵심 항목과 원본 관계의 근거가 있는 독립 발견을 먼저 보여줍니다. 확정 오류와 자동 발견을 구분하며, 재무 항목별 필터와 접힌 추가 필터를 제공합니다. 전체 분석 수와 다른 원본의 반복·파생·보류 기록은 상세 영역에서 언제든 펼쳐 볼 수 있습니다.
3. ‘판단 근거 보기’에서 파일명·셀/문단/표 위치·원문·계산식·규칙 코드·신뢰도·기준 조건을 확인합니다. 기본 목록에서는 원본 파일명이나 규칙 코드를 노출하지 않습니다.
4. ‘이 항목 검토’를 누르면 해당 결과에서 문서 간 비교를 인라인으로 확인합니다. ‘예’는 실제 부족한 공통 기준일·시나리오·기간·단위를 입력한 뒤 기존 연결 승인 경로로 전달합니다. 가정·조건부 값을 확정으로 바꾸려면 별도 확인이 필요하며, 미선택 시 원래 상태를 유지하고 판정을 보류합니다. ‘아니요’와 ‘확인할 수 없음’은 해당 연결 승인을 해제하되 원래 수치 차이를 유지합니다. 복잡한 수정은 ‘고급 편집·개별 승인’ 또는 상세 검토에서 수행합니다. 고급 화면의 ‘추천 구성만 적용’은 승인하지 않습니다.
5. ‘자동 발견 · 확인 필요’와 ‘사용자 확인 후 · 오류/통과/확인 필요’를 구분합니다. 원문 조건이 다르거나 불명확하면 승인 후에도 확정 오류로 바뀌지 않습니다. 전체 항목 수정은 ‘상세 검토’, 수동 계산·배정·계획·세션 설정은 결과 하단 ‘고급 검사 설정·승인 결과’에 있습니다.
6. 필요할 때만 아래 임시 저장에 동의하고 확인 상태를 저장합니다. 새로고침 후 원본 파일을 다시 올려 명시적으로 복원합니다.

대출 약정·배정 기간·승인/수령 등 누락된 조건은 고급 설정에서 확인해야 합니다. 추천을 승인해도 가정·조건부·시점 차이·누락 조건을 자동으로 확정으로 바꾸지 않습니다.

상세 기능:

다음은 필요한 경우 사용하는 고급 경로입니다. 검사 실행의 선행 조건이 아닙니다.

1. Excel 재무표 영역에서 `.xlsx`를 선택합니다.
2. ‘원본 상세 보기’를 열고 시트를 선택해 셀 주소, 원본 값, XML 저장값, 수식 및 저장된 계산 결과를 확인합니다.
3. Word 보고서 영역에서 `.docx`를 선택하고 ‘원본 상세 보기’에서 문단과 표의 원문·행열 위치·숫자 문맥을 확인합니다.
4. ‘상세 검토’에서 항목명·유형, 숫자·단위, 기준일·적용 기간·시나리오, 확정 여부를 수정합니다. 원문 문맥을 펼쳐 확인하고 ‘확인 완료’를 선택합니다.
5. 잘못 추출된 후보는 제외하고, ‘제외됨’ 필터에서 복원할 수 있습니다. 누락된 항목은 직접 추가하고 원본 종류·참조 위치를 지정합니다.
6. Excel·Word 선택 목록이나 연결 제안에서 ‘연결 승인’을 선택합니다. 항목 확인 완료와 연결 승인은 별개입니다. 하나의 값에 여러 원본 후보를 연결할 수 있습니다.
7. 숫자·단위 등 후보를 수정하거나 제외하면 해당 후보의 사용자 확인 및 관련 연결 승인이 해제됩니다. 파일 교체·초기화는 해당 종류의 후보(직접 추가 포함)와 관련 연결을 제거합니다.
8. ‘검수 결과’에서 계산별 검사 대상과 구성 항목을 선택합니다. 필요한 항목만 확인하면 되며, 모든 후보의 확인 완료를 요구하지 않습니다. 여러 문서의 합계를 섞지 않고 소계·합계와 구성 항목을 중복 선택하지 않습니다.
9. 범위 완전성 확인란을 선택합니다. 월 잉여금은 모든 입력을 월간으로 확인해야 합니다. 지출·저축이 없다면 0원 항목을 직접 추가해 확인하고, 원본 종류·참조 파일명·위치를 해당 문서에 맞게 입력합니다. 대출은 상환방식, 거치기간(없으면 0), 최초 원금·전체 기간 또는 현재 잔액·잔여 기간을 명시합니다.
10. 결과의 코드·제목 버튼으로 원문·수치·판단 근거를 펼치고 ‘관련 항목 확인·수정’으로 해당 항목만 검토합니다. 편집·제외는 계산 범위 확인을 해제하며 파일 교체는 관련 선택을 비웁니다. 결과는 현재 입력으로 즉시 다시 계산됩니다.
11. 같은 화면의 ‘자금 배정 및 계획 확인’에서 보유 자산 후보와 목표액 후보를 연결하고 배정액·기간·시나리오를 입력합니다. 같은 실물 자산은 반드시 같은 후보 ID를 선택합니다. 이름만 같거나 문서에 반복된 후보는 자동 병합하지 않습니다.
12. 조건부 금액은 승인·수령·확정 여부, 반영일, 반영처와 현재 검토 기준일을 확인합니다. 예상/참고 시나리오는 현재 확정 자산·수입과 별도로 표시합니다.
13. 제안·실행은 같은 대상을 같은 대상 ID로 연결하고 행동·기간·시나리오를 확인합니다. 기존 ETF 보유 유지와 신규 ETF 적립 중단처럼 대상 범위가 다르면 ID를 구분합니다. 중단이라는 단어만으로 무조건 유지의 반대라고 확정하지 않습니다.
14. 자동 후보는 미확인입니다. 원본 행·문단이나 기존 추출 항목에 연결하고 구조화 확인란을 선택해야 오류 판정에 사용됩니다. 편집은 확인을 해제하며, 파일 교체는 해당 원본에 의존하는 구조화 항목을 제거합니다. 제외된 항목은 복원 후 다시 확인할 수 있습니다.

서버 업로드·외부 AI API·원문 영구 저장은 구현하지 않았습니다. 새로고침하면 원문과 수정 데이터는 사라집니다. 파일 내용은 HTML로 실행하지 않고 텍스트로 표시합니다.

## 자동 추천과 승인

- 계산은 같은 문서의 표·시트와 월·연 구분을 사용합니다. 자산·부채의 참고 합계는 제외하고 지출·저축은 소계와 구성원을 중복 선택하지 않도록 추천합니다. 단, 구성 범위의 완전성은 사용자가 확인합니다.
- 순자산은 같은 표·시트의 총자산·총부채를 제안합니다. 대출은 이름이 같은 약정 후보를 찾고 여러 원금·잔액·기간이 있으면 하나를 임의 선택하지 않습니다. 다른 대출 이름, 다른 명의가 명시된 항목은 연결하지 않습니다.
- CROSS는 금액 일치 여부를 선택 기준으로 사용하지 않습니다. 반복 출현은 유지하고 구조·기간이 가까운 후보를 먼저 보여줍니다. 대표 추천이 원본 동일성을 보증하지 않습니다.
- ALLOC는 원문에 ‘자산 금액을 목표에 배정/할당’ 관계가 명시되어 있고 두 이름의 후보가 각각 유일한 경우에만 미확인 배정 구성을 가져옵니다. 명시되지 않거나 모호한 관계는 직접 확인으로 안내합니다.
- PLAN은 기존 조건부 금액·행동 후보의 근거와 미확인 항목으로 안내합니다. 승인·수령·기간·행동을 새로 추론하지 않습니다. 대상 ID가 같은 제안·실행과 등록된 배정은 확인 화면으로 연결합니다.
- 추천 신뢰 상태와 사용자 확인 여부는 별개입니다. 불확실 후보를 추천만으로 승인하지 않고, 확인 버튼도 가정·조건부 상태를 ‘확정’으로 덮어쓰지 않습니다.

## 세션 내 확인 상태 저장

- 기본은 저장하지 않습니다. 동의 확인란과 저장 버튼을 모두 선택했을 때만 탭의 `sessionStorage`에 체크포인트를 만듭니다. `localStorage`에는 쓰지 않습니다.
- 저장 내용은 전체 파일 SHA-256 지문, 임의 nonce로 구분한 후보/연결 해시, 확인·제외 불리언, 저장 시각입니다. 원문·금액·파일명·셀 주소·수정값·직접 추가 항목·계산 설정·구조화 계획은 저장하지 않습니다. 해시는 암호화 문서 백업이 아닙니다.
- 새로고침 후 같은 파일을 모두 재업로드하고 동의·복원 버튼을 눌러야 합니다. 한 바이트라도 다르거나 파일 일부만 선택되면 복원하지 않습니다. 자동 복원은 없습니다.
- 저장된 숫자나 편집 내용을 복원하는 기능이 아닙니다. 다시 추출된 항목과 편집 내용까지 동일한 확인 상태만 복원됩니다. 수정했던 값·기준일·시나리오·확정 상태는 저장하지 않으므로 다시 입력·확인해야 할 수 있습니다.
- 계산 범위·계획 확인은 복원하지 않으며 현재 범위 확인도 해제합니다. 저장·복원 중 문서나 검토 상태가 바뀌면 취소합니다. 저장 공간 차단·Web Crypto 미지원 환경에서는 사용할 수 없습니다.
- ‘임시 저장 삭제’로 체크포인트를 지울 수 있습니다. 탭 세션 수명은 브라우저의 세션 복원 정책에 따릅니다.

## 코드 구조

화면 글꼴은 Pretendard Variable로 통일합니다. `pretendard` 패키지의 WOFF2를 빌드에 포함하므로 외부 CDN이나 폰트 서버에 요청하지 않습니다. 흰색·회색 작업 영역과 남색 강조색, 간결한 제목과 표 중심 구성을 사용합니다.

- `src/parsers/package.ts`: 파일 검사 및 ZIP/XML 공통 처리
- `src/parsers/xlsx.ts`: 워크북 관계, 공유 문자열, 시트, 셀, 수식 캐시, 병합 영역 추출
- `src/parsers/docx.ts`: 본문 문단, 표, 셀 병합, 숫자 원문 추출
- `src/parsers/types.ts`: UI와 분리된 추출 데이터 형식
- `src/normalization/types.ts`: 원문·위치·숫자·단위·정규화 값·항목 유형·시점·확정 여부·사용자 확인·추출 방식·신뢰 상태 모델
- `src/normalization/extract.ts`: 항목명·행·열·문단 근접 문맥 기반 후보 추출
- `src/normalization/values.ts`: 원 단위 변환, 입력 검사, 편집 시 확인 해제
- `src/normalization/links.ts`: 명칭·유형·단위 기반 연결 제안과 승인 무효화
- `src/components/DocumentPanel.tsx`: 파일 선택, 오류, 초기화, 비동기 응답 순서 제어
- `src/components/WorkbookView.tsx`, `WordView.tsx`: 추출 결과 표시
- `src/components/ReviewView.tsx`: 후보 편집·확인·제외·직접 추가 및 수동 연결 승인
- `src/validation/types.ts`: 계산별 역할·선택 범위·대출 조건·검증 결과 모델
- `src/validation/engine.ts`: React·DOM과 독립적인 순수 CALC·CROSS 함수와 원리금균등 계산
- `src/inspection/analyze.ts`: 기존 추천과 엔진을 재사용하는 자동 검사 조합·근거·질문·승인 결과 모델
- `src/validation/discovery.ts`: 자동 발견 경로의 오류·통과 판정을 참고 후보로 제한하는 공통 경계
- `src/components/InspectionResults.tsx`: 간결한 후보 목록과 선택 항목 검토
- `src/presentation/format.ts`: 원·만 원·억 원·금리·%p·기간 표시와 미세한 비영 값 처리
- `src/presentation/findingGroups.ts`: 네 판정 상태 및 공유 원본 그룹화(개별 근거 유지)

## 검증 기준

- CALC: 총자산·총부채 구성 합계, 순자산 차감, 월 소득−지출−저축, 원리금균등 월 상환액을 검사합니다. 선택하지 않은 후보는 자동으로 합산하지 않습니다. 자산은 예금·ETF·퇴직연금·보증금, 부채는 대출 잔액 유형을 지원합니다.
- CROSS: 승인 연결의 원 단위 금액·% 금리·개월 기간을 비교합니다. 년은 개월로 환산합니다. 값이 달라도 기준일·기간·시나리오가 다르거나 미확인 상태라면 확정 오류로 판정하지 않습니다.
- ALLOC_CAPACITY: 자산 ID·시나리오·현재/미래 자금 구분별로 기간이 겹치는 최대 배정액을 계산합니다. 현재 자산의 최대 동시 배정액이 확인된 보유액보다 크면 오류입니다. 미래 적립금은 따로 보류하며 현재 자산 그룹의 확정 초과 배정을 숨기지 않습니다. 시작일·종료일을 모두 포함하므로 같은 날짜에 종료·시작하면 겹칩니다.
- PLAN_CONDITIONAL: 미승인·미수령으로 확인된 가정/조건부 금액이 검토 기준일 현재의 확정 자산·수입에 반영되면 오류입니다. 승인·수령 여부가 확인된 예상 시나리오·미반영은 해당 선반영 규칙을 통과합니다. 승인·수령이 미확인이면 예상 시나리오도 보류합니다. 승인 후 미수령 금액의 가용 현금 여부와 상충된 확인 정보는 보류합니다. 확정 승인 수입의 회계적 인식 적정성까지 판정하지 않습니다.
- PLAN_CONFLICT: 같은 대상 ID의 제안·실행을 비교합니다. 동일 시나리오·겹치는 기간에서 중단↔유지/시작/증액, 증액↔감액은 충돌입니다. 같은 중단끼리는 충돌하지 않습니다. 다른 행동 조합, 금액·단위 차이, 0원 행동의 실질 충돌 여부는 보류합니다. 상대 계획이 없으면 검증 불가입니다.
- `검증 불가`: 필수 입력 누락, 사용자 미확인, 제외 항목, 숫자·단위·유형 오류 등으로 계산 근거가 부족한 경우입니다. 누락된 항목을 결과에 안내합니다.
- `확인 필요`: 범위 미확인, 서로 다른 문서의 계산 입력, 기준일·시나리오 불명확, 가정·조건부 값, 월·연 구분 또는 대출 조건이 불명확한 경우입니다. 약정이 불명확한 대출은 계산값을 표시하지 않습니다.
- `오류` / `검증 통과`: 사용자 확인·확정 상태와 동일 기준·범위가 갖춰진 경우에만 허용오차로 판정합니다. 통과는 해당 계산·연결에 한정하며 문서 전체의 정상 판정이 아닙니다.
- CALC 허용오차는 기본 1원이며 사용자가 변경할 수 있습니다. CROSS는 원 단위 1원, 금리·기간은 1e-8 단위입니다. 차이는 문서값−계산값, CROSS는 Excel−Word입니다. 월 상환액은 원 단위 반올림이며 % 차이는 %p입니다.
- 대출은 고정 연금리·원리금균등·거치 0개월만 지원합니다. 무이자는 원금/개월, 이자가 있으면 `P×r/[1−(1+r)^(-n)]`이며 r=연금리/1200입니다. 상환방식·기간 기준·거치 여부는 사용자가 원문 약정에서 확인합니다.

문서 파서는 JSZip과 브라우저 DOMParser로 OOXML을 직접 읽습니다. 실제 제공 문서의 파싱 테스트를 바탕으로 선택했습니다. 수식 실행이나 서식 재현보다 원본 위치, 저장값, 문단·표 구조 보존에 우선순위를 둡니다.

## 실제 샘플 테스트

팀원 회귀 자료는 `PLANCHECK_TEAM_XLSX`와 `PLANCHECK_TEAM_DOCX`에 로컬 경로를 지정합니다. 파일은 Git 제외 대상이며 `tests/team-feedback.test.ts`와 `e2e/feedback.spec.ts`가 읽기 전용으로 검사합니다. 단위 상속·원문 비교·미래 시점 구분의 변경 전후는 [최종 피드백 기록](docs/final-feedback.md)에 정리했습니다. 불명확한 단위는 상세 검토의 ‘표·열 단위 일괄 지정’에서 수정할 수 있으며, 변경 후 관련 값과 연결을 다시 확인해야 합니다.

개인 문서를 저장소에 넣지 않고 환경변수로 지정합니다. 두 경로가 없으면 실제 샘플 테스트 16개는 건너뜁니다. 정규화·검증 통합 테스트는 월 소득 315만 원, 예금·적금, 총자산·총부채·순자산, 신용대출 금리, 학자금대출 잔액, 잉여금과 퇴직연금 후보를 확인합니다. 계획 통합 테스트는 실제 문서의 행동·조건부 금액 후보와 원본 위치 보존, 미확인 후보의 확정 오류 방지를 검사합니다. 검증 테스트는 사용자 미확인 및 원래 문맥 차이에 대한 보류와, 사용자가 기준을 맞춰 확인한 경우의 숫자 비교를 구분합니다. 원본 숫자는 바꾸지 않으며 실제 값은 테스트 기대값으로만 사용합니다.

```powershell
$env:PLANCHECK_XLSX = 'C:\path\sample.xlsx'
$env:PLANCHECK_DOCX = 'C:\path\sample.docx'
npm.cmd test
```

## 실제 브라우저 시연

E2E는 프로덕션 빌드와 설치된 Chrome으로 실제 파일 선택·검사 시작·클릭·입력·승인을 테스트합니다. `automatic.spec.ts`는 승인 없이 발견한 차이와 확인 후 확정 오류를 구분하고, `demo.spec.ts`와 `onboarding.spec.ts`는 기존 고급 편집·원본·초기화·중복 배정 회귀를 유지합니다. Chrome 대신 설치된 Edge는 `PLANCHECK_BROWSER_CHANNEL=msedge`로 선택합니다. 포트 4173은 비워 둡니다.

```powershell
$env:PLANCHECK_XLSX = 'C:\path\sample.xlsx'
$env:PLANCHECK_DOCX = 'C:\path\sample.docx'
npm.cmd run build
npm.cmd run test:e2e
# 창을 표시하며 같은 흐름 실행
npm.cmd run test:e2e:headed
```

- 자료 없음 안내, 핵심 추천, 사용자 확인 전 오류 0건, 원문 조건 차이의 보류, 승인 후 신용대출 금리·학자금대출 잔액 차이, 원본 위치·문맥, 파일 재업로드 초기화를 확인합니다.
- 숫자는 원문 그대로 유지합니다. 확정 오류 시연에서는 사용자가 동일 기준일·시나리오·확정 상태를 확인한 경우를 별도로 입력합니다. 서로 다른 원문 조건을 자동으로 같다고 판단하지 않습니다.
- 중복 배정 시연은 실제 예금 보유액과 사용자가 직접 추가한 두 시연 목표·동시 배정 관계를 사용합니다. 원문에서 두 목표 관계가 추출됐다는 뜻이 아닙니다.
- 테스트 중 외부 요청이나 문서 전송 요청이 없는지도 검사합니다. 스크린샷과 실패 추적에는 금융 정보가 포함될 수 있어 `test-results/`, `playwright-report/`는 Git에서 제외합니다.
- 경로 미지정 시 실제 문서 E2E 12개는 건너뜁니다. 예시 기대값은 테스트에만 있고 앱의 추천·검증 엔진에는 포함하지 않습니다.

`inline-review.spec.ts`는 실제 문서에서 예·아니요·미확인, 누락 조건 질문, 가정 상태 보존, 확정 상태의 명시적 확인, 기존 연결 승인과의 일치, 편집 후 재계산, 390px 모바일·1280px 노트북 가로 넘침을 검사합니다.

결과는 오류 설명을 먼저, 규칙 코드를 보조로 표시합니다. 검증 불가는 검증 준비 중이라는 설명과 다음 행동을 함께 표시하고 추천 검토·승인이나 구조화 조건 확인으로 이동합니다. 승인 후 결과 필터는 판정 결과로 돌아와 새 오류가 가려지지 않습니다.

## 첫 사용자 안내

- 검사 시작 → 검사 결과 → 필요한 부분만 상세 검토의 흐름이며 현재 화면을 표시합니다. 상세 작업 안내는 기본적으로 접혀 있습니다. 기존 단계별 도움말의 닫기 상태는 앱 실행 중 기억하며 새로고침하면 초기화됩니다.
- 다음 행동은 실제 파일 등록 상태, 핵심 후보의 사용자 확인, 추천 승인, 검증의 누락 조건에 따라 달라집니다. 파일 등록 위치, 관련 핵심 후보, 추천 검토 또는 계산 조건으로 이동합니다. 안내가 항목을 자동 승인하지 않습니다.
- 데이터 확인은 핵심 추천의 구성 후보와 주요 재무 항목·직접 입력을 우선 표시합니다. 전체 후보는 목록 필터의 ‘전체’로 접근합니다. 핵심 후보의 사용자 확인 진행률은 검증 통과율이 아니며 전체 확인은 실행 조건이 아닙니다.
- `e2e/onboarding.spec.ts`는 안내 닫기·재열기, 누락 파일 등록 위치, 두 파일 등록 후 이동, 원본 접기·펼치기, 핵심 확인 바로 이동과 검증 준비 경로를 실제 Chrome에서 검사합니다. 기존 금리·잔액·중복 배정 시연도 유지합니다.
- 핵심 선택과 다음 행동은 제한된 문맥·등록 상태를 이용한 안내입니다. 문서의 의미나 추천 완전성을 보장하지 않으므로 원본을 확인해야 합니다. 실제 첫 사용자 대상 사용성 실험은 별도입니다.

## 자동 검사 안전성과 한계

- 자동 발견은 `confirmed`나 `scopeConfirmed`를 true로 바꾸거나 승인 연결을 저장하지 않습니다. 엔진의 같은 계산·비교 함수를 사용하되 자동 경로는 사용자 확인 게이트만 별도로 다룹니다. 기존 확정 검증 경로는 동일한 승인 조건을 유지합니다.
- 추천된 범위에서 수치가 다르면 차이를 보여줄 수 있지만 동일 대상·동일 시점·범위의 완전성은 확정하지 않습니다. 자동 경로는 오류/통과를 반환하지 않습니다. 수치가 같아도 ‘수치 일치 후보’이며 전체 정상이라는 뜻이 아닙니다.
- 원본에 명시된 자산→목표 배정만 후보로 가져옵니다. 사용 시점·대체 시나리오·미래 적립금은 채우지 않습니다. 조건부 금액은 실제 반영처·승인·수령을, 행동은 대상·기간·시나리오를 확인해야 합니다.
- 지원금 설명이나 일반적인 제안 문장이 계획 후보에 섞일 수 있습니다. 정보 부족·반복 후보를 별도로 유지하고 유형 필터에서 확인할 수 있으며 잘못된 후보는 고급 검토에서 제외할 수 있습니다. 단순 언급만으로 선반영 오류나 행동 충돌을 만들지 않습니다.
- 파일 교체·초기화는 자동 검사 결과를 비웁니다. 두 파일을 등록하고 다시 검사해야 하며, 원문·수정·승인 상태는 기존 개인정보 저장 정책을 따릅니다. 외부 AI나 서버는 사용하지 않습니다.

## 결과 표시와 인라인 검토 정책

- 베타 화면에서는 ‘확인된 오류’와 ‘검사 중 발견·확인 필요’를 구분합니다. 내부 검증 상태와 승인 조건은 그대로이며, 개인정보 안내는 파일 등록 화면에만 표시합니다. 화면 기준과 브라우저 점검 범위는 [베타 UI 점검 기록](docs/beta-ui-review.md)에 정리했습니다.

- 기본 화면은 ‘우선 확인할 문제’와 ‘추가 확인’을 중심으로 보여주며 전체 분석 수와 파생 후보는 접힌 상세 분석 기록에 둡니다. 같은 원본 쌍의 현재 사용자 승인은 재검토 시 재사용하지만, 자동 후보나 다른 위치에 승인을 확장하지 않습니다. 수정·제외·파일 교체 후에는 다시 확인해야 합니다.
- [실제 문서 정확도 평가](docs/accuracy-evaluation.md)는 원본 복사본에 독립 주입한 5가지 오류를 평가합니다. 구체적 자동 발견 2/5와 수동 조건 확인 후 최종 판정 5/5를 구분합니다. 정상·수정 관계 및 다른 기준일·시나리오도 검사하며 이 수치를 전체 문서의 일반적인 정확도로 해석하지 않습니다.
- `PLANCHECK_ACCURACY_EXPORT=1`로 `tests/accuracy.test.ts`를 실행하면 Git 제외된 `test-results/accuracy-fixtures/`에 원본 구조를 보존한 오류·정상 복사본 10쌍과 집계 JSON을 만듭니다. 원본 금융 내용이 포함되므로 공개하지 않습니다. Chrome E2E 실행 시 이 폴더는 초기화됩니다.

- 우선순위는 핵심 항목·대상 식별·원본 구조·단위·기간 근거로 정합니다. 금액 차이 크기로 정렬하거나 개수 상한으로 자르지 않습니다. 완전 중복만 합치고 다른 원본·근거는 상세 기록에 보존합니다. 명시적 기간·시나리오 차이는 직접 비교보다 조건 확인을 우선합니다.
- 개별 금액과 묶음 금액, 보유액과 납입액, 상환방식 코드와 실제 상환액은 자동 연결·승인을 제한합니다. 합계·소계 중복이나 납입액 역할이 불명확한 계산 추천은 자동 계산을 보류합니다. 상세 편집과 계산 범위 확인은 유지합니다.
- 실제 253건의 변경 전후 유형·보류 원인·오탐과 우선 검토 7건의 근거는 [품질 분석 보고서](docs/result-quality-analysis.md)에 기록했습니다. `tests/result-quality-samples.test.ts`로 재현하고 `PLANCHECK_QUALITY_AUDIT=after`를 설정하면 Git 제외된 `test-results`에 원문 포함 감사 JSON을 생성합니다. 이 파일은 공개하지 않습니다.
- `e2e/result-quality.spec.ts`는 실제 Chrome에서 우선 발견·재무 항목 필터·부적합 연결 기록·모바일 넘침을 검사합니다. 기존 승인·수정·원본·초기화 E2E도 유지합니다.

- 내부 정규화 값과 원본 숫자는 표시용 반올림으로 바꾸지 않습니다. 차이는 기존 엔진이 원본 정규화 값으로 계산한 값을 사용합니다. 원은 정수·쉼표, 만/억 원은 최대 소수 두 자리이며 실제 반올림한 값은 두 자리를 남깁니다(예: `4.6019981146635018만 원` → `4.60만 원`, `701.5만 원` → `701.5만 원`). 금리는 최대 두 자리, %p는 최소 한 자리입니다.
- 반올림 시 0이 되는 비영 값은 원 단위로 전환하거나 최대 여섯 자리·‘미세한 차이’로 구분합니다. 누락·파싱 실패는 0으로 표시하지 않습니다. 원문 인용과 편집 입력은 원래 문자열을 보존하므로 원본 상세에는 원문 정밀도가 남습니다.
- 인라인의 ‘같은 기준’은 날짜·시나리오·확정 상태를 추론하지 않습니다. 원문 조건을 대조해 사용자가 직접 확인해야 하며 다른 대출이나 유효하지 않은 숫자·단위는 간단한 예 선택만으로 승인하지 않습니다.
- ‘다른 조건’과 ‘확인 불가’ 결정은 현재 앱 메모리에만 유지됩니다. 해당 원본·수치·조건의 편집, 관련 연결 승인/해제, 파일 교체·복원 시 오래된 결정을 해제합니다. 새로고침 후 인라인 답변을 자동 복원하지 않습니다. 기존 체크포인트 저장 기능의 범위는 동일합니다.
- 그룹은 원본을 재사용한다는 표시이며 같은 계좌·같은 재무목표라는 확정이 아닙니다. 서로 다른 근거의 결과는 추가 후보로 모두 보존하고 각자 검토할 수 있습니다. 보류나 반복 후보 수를 감추거나 통과로 바꾸지 않습니다.

데이터 확인의 기본 목록은 항목명·값과 단위·원본·확인 상태만 보여줍니다. 상세 편집을 열면 모든 기존 필드를 수정할 수 있고 항목명·원본 위치로 검색할 수 있습니다. ZIP 라이브러리는 실제 파일을 열 때 불러옵니다.

## 범위와 한계

- 수식을 재계산하지 않습니다. 캐시 누락·오류는 `확인 필요`, 존재하는 캐시는 `미검증`으로 표시합니다. 공유 수식의 종속 셀은 참조 식별자를 보존하고 식을 재구성하지 않습니다.
- Excel 원시 화면은 XML 저장값입니다. 후보 추출에서는 숫자 서식의 `%`와 명시된 단위를 이용합니다. 날짜 일련번호와 임의 사용자 서식은 해석하지 않습니다. 단위 근거가 없으면 정규화 값은 null입니다.
- Word는 `word/document.xml` 본문만 처리합니다. 머리글·바닥글, 주석, 텍스트 상자, 도형, 변경 추적과 필드 계산값을 완전히 해석하지 않습니다.
- Word 가로 병합은 열 수로, 세로 병합은 시작/계속 표기로 보존합니다. 중첩 표는 셀의 문단 텍스트로 평탄화합니다. 페이지 번호와 인쇄 레이아웃은 재현하지 않습니다.
- 후보 추출은 한국어 항목명과 제한된 문맥 규칙을 사용합니다. 모든 자동 후보는 사용자 미확인 상태입니다. 숫자 등장만으로 확정하지 않으며, 반복 후보를 합치지 않습니다. 누락·파싱 실패는 0으로 바꾸지 않습니다.
- 원·만 원·억 원은 원 단위로 반올림합니다. 금리는 % 숫자, 기간은 선택한 개월·년 단위를 유지합니다. JavaScript 안전 정수 범위를 넘는 금액은 정규화하지 않습니다.
- 복잡한 수식 설명, 복합 금액(예: 1억 2천만 원), 범위, 중첩 표와 목표·재원·기한의 정확한 관계는 자동 확정할 수 없습니다. 목표명·재원·기한은 텍스트 후보로 제공하며 수정·직접 추가가 필요할 수 있습니다.
- 기준일은 명시 문맥에서만 가져오며 날짜를 표준화하지 않습니다. 적용 기간과 시나리오는 원문 또는 사용자 입력 문자열입니다. 연결 제안은 금액 차이로 제거하지 않고 기준일·기간·시나리오 차이를 표시합니다. 제안은 동일성이나 오류의 판정이 아닙니다.
- 원문·수정값·계산 설정·구조화 계획은 메모리에서만 유지됩니다. 새로고침하면 사라집니다. 확인·제외 상태와 승인 연결은 동의 후 해시만 세션 저장할 수 있습니다. 변동금리·거치부·만기일시·원금균등·중도상환·수수료·일할 이자는 지원하지 않습니다. 외부 AI API는 사용하지 않습니다.
- ALLOC의 통과는 선택된 동일 자산 ID의 동시 배정 용량에 한정됩니다. 서로 다른 후보 ID가 실제 같은 계좌인지, 사용 후 원금 소진·재충전·유동성 제한·순차 현금흐름은 자동 검증하지 않습니다. 순차 사용이나 미래 자금이 있다고 계획 전체를 정상으로 판단하지 않습니다.
- 구조화 계획의 날짜는 `YYYY-MM-DD`만 지원합니다. 자연어 기한·조건·대체 시나리오·대상 동일성은 사용자가 확인해야 합니다. 텍스트 후보는 제한된 어휘로 찾으므로 범용 자연어 이해가 아닙니다. 복수 행동·부정 표현은 미확인으로 두며 ‘자동이체 중단’을 유지로 추론하지 않습니다. 명시적인 배정 문장과 유일한 대상이 있을 때만 미확인 관계 후보를 제안하며, 다른 관계는 생성하지 않습니다.
- 조건부 금액의 자동 후보에는 일반적인 지원비·보험 설명 등이 섞일 수 있습니다. 금액이 여러 개이거나 범위이면 비워 두며 승인·수령·반영일·반영처는 추론하지 않습니다. 원본 문맥을 확인하고 잘못 추출된 후보는 제외하세요.
- 기준일·시나리오의 문자열을 공백 제거 후 비교하며 서로 다른 표기법을 임의로 같은 날짜로 처리하지 않습니다. 구성 범위의 완전성, 같은 대출의 약정 여부, 추출 후보의 의미는 사용자가 확인해야 합니다. 컴포넌트 테스트는 jsdom, E2E는 실제 Chrome에서 실행합니다. 명시한 시연 흐름 외 모든 문서·브라우저의 호환성을 보장하지 않습니다.
- 파일 30MB, Excel 셀 100,000개, 읽은 XML 누적 100MB를 제한합니다. ZIP 엔트리의 압축 해제 후 용량을 검사하므로 악의적 압축 파일에 대한 완전한 메모리 보호 장치는 아닙니다. 대형 문서는 메인 스레드에서 처리되어 잠시 응답이 느려질 수 있습니다.

개인 샘플과 로컬 개발 지침·환경 파일은 `.gitignore`로 제외합니다.
