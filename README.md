# PlanCheck

Excel 재무표와 Word 보고서의 원본을 브라우저에서 추출하고, 주요 재무 항목 후보를 사용자가 확인·수정하는 작업 도구입니다. 계산 오류 판정과 전체 검증 엔진은 아직 구현하지 않았습니다.

## 실행

Node.js 22.12 이상을 사용합니다.

```sh
npm ci
npm run dev
npm test
npm run build
npm run lint
```

PowerShell 실행 정책으로 npm.ps1이 차단되면 `npm.cmd`를 사용합니다.

## 사용

1. Excel 재무표 영역에서 `.xlsx`를 선택합니다.
2. 시트를 선택하고 셀 주소, 원본 값, XML 저장값, 수식 및 저장된 계산 결과를 확인합니다.
3. Word 보고서 영역에서 `.docx`를 선택하고 문단과 표의 원문·행열 위치·숫자 문맥을 확인합니다.
4. ‘데이터 확인’ 단계에서 항목명·유형, 숫자·단위, 기준일·적용 기간·시나리오, 확정 여부를 수정합니다. 원문 문맥을 펼쳐 확인하고 ‘확인 완료’를 선택합니다.
5. 잘못 추출된 후보는 제외하고, ‘제외됨’ 필터에서 복원할 수 있습니다. 누락된 항목은 직접 추가하고 원본 종류·참조 위치를 지정합니다.
6. Excel·Word 선택 목록이나 연결 제안에서 ‘연결 승인’을 선택합니다. 항목 확인 완료와 연결 승인은 별개입니다. 하나의 값에 여러 원본 후보를 연결할 수 있습니다.
7. 숫자·단위 등 후보를 수정하거나 제외하면 해당 후보의 사용자 확인 및 관련 연결 승인이 해제됩니다. 파일 교체·초기화는 해당 종류의 후보(직접 추가 포함)와 관련 연결을 제거합니다.

서버 업로드, 외부 API, 저장소 전송, 로컬 영구 저장은 구현하지 않았습니다. 새로고침하면 문서 데이터가 사라집니다. 파일 내용은 HTML로 실행하지 않고 텍스트로 표시합니다.

## 코드 구조

화면 글꼴은 Pretendard Variable로 통일합니다. `pretendard` 패키지의 WOFF2를 빌드에 포함하므로 외부 CDN이나 폰트 서버에 요청하지 않습니다. 흰색·회색 작업 영역과 남색 강조색, 간결한 제목과 표 중심 구성을 사용합니다.

- `src/parsers/package.ts`: 파일 검사 및 ZIP/XML 공통 처리
- `src/parsers/xlsx.ts`: 워크북 관계, 공유 문자열, 시트, 셀, 수식 캐시, 병합 영역 추출
- `src/parsers/docx.ts`: 본문 문단, 표, 셀 병합, 숫자 원문 추출
- `src/parsers/types.ts`: UI와 분리된 추출 데이터 형식
- `src/normalization/types.ts`: 원문·위치·숫자·단위·정규화 값·항목 유형·시점·확정 여부·사용자 확인·추출 방식·신뢰 상태 모델
- `src/normalization/extract.ts`: 항목명·행·열·문단 근접 문맥 기반 후보 추출
- `src/normalization/values.ts`: 원 단위 변환, 입력 검사, 편집 시 확인 해제
- `src/normalization/links.ts`: 명칭·유형·단위 기반 연결 제안과 승인 무효화
- `src/components/DocumentPanel.tsx`: 파일 선택, 오류, 초기화, 비동기 응답 순서 제어
- `src/components/WorkbookView.tsx`, `WordView.tsx`: 추출 결과 표시
- `src/components/ReviewView.tsx`: 후보 편집·확인·제외·직접 추가 및 수동 연결 승인
- `src/components/ui`: shadcn/ui 구성 방식의 기본 UI 요소
- `tests`: 파서, 파일 변경, 실제 샘플 통합 테스트

React + TypeScript + Vite, Tailwind CSS, shadcn/ui 방식의 Radix Slot/CVA 버튼, TanStack Table 8, Lucide를 사용합니다. 원시 데이터는 각 문서 컴포넌트에, 확인 후보와 연결은 App에 유지합니다. 정규화 로직은 React와 DOM에 의존하지 않습니다.

문서 파서는 JSZip과 브라우저 DOMParser로 OOXML을 직접 읽습니다. 실제 제공 문서의 파싱 테스트를 바탕으로 선택했습니다. 수식 실행이나 서식 재현보다 원본 위치, 저장값, 문단·표 구조 보존에 우선순위를 둡니다.

## 실제 샘플 테스트

개인 문서를 저장소에 넣지 않고 환경변수로 지정합니다. 두 경로가 없으면 실제 샘플 테스트 3개는 건너뜁니다. 정규화 통합 테스트는 양쪽 문서의 월 소득 315만 원, 예금·적금, 총자산·총부채, 신용대출 금리, 학자금대출 잔액, 잉여금과 퇴직연금 후보를 확인합니다. 실제 값은 테스트의 기대값으로만 사용하며 애플리케이션에 주입하지 않습니다.

```powershell
$env:PLANCHECK_XLSX = 'C:\path\sample.xlsx'
$env:PLANCHECK_DOCX = 'C:\path\sample.docx'
npm.cmd test
```

## 범위와 한계

- 수식을 재계산하지 않습니다. 캐시 누락·오류는 `확인 필요`, 존재하는 캐시는 `미검증`으로 표시합니다. 공유 수식의 종속 셀은 참조 식별자를 보존하고 식을 재구성하지 않습니다.
- Excel 원시 화면은 XML 저장값입니다. 후보 추출에서는 숫자 서식의 `%`와 명시된 단위를 이용합니다. 날짜 일련번호와 임의 사용자 서식은 해석하지 않습니다. 단위 근거가 없으면 정규화 값은 null입니다.
- Word는 `word/document.xml` 본문만 처리합니다. 머리글·바닥글, 주석, 텍스트 상자, 도형, 변경 추적과 필드 계산값을 완전히 해석하지 않습니다.
- Word 가로 병합은 열 수로, 세로 병합은 시작/계속 표기로 보존합니다. 중첩 표는 셀의 문단 텍스트로 평탄화합니다. 페이지 번호와 인쇄 레이아웃은 재현하지 않습니다.
- 후보 추출은 한국어 항목명과 제한된 문맥 규칙을 사용합니다. 모든 자동 후보는 사용자 미확인 상태입니다. 숫자 등장만으로 확정하지 않으며, 반복 후보를 합치지 않습니다. 누락·파싱 실패는 0으로 바꾸지 않습니다.
- 원·만 원·억 원은 원 단위로 반올림합니다. 금리는 % 숫자, 기간은 선택한 개월·년 단위를 유지합니다. JavaScript 안전 정수 범위를 넘는 금액은 정규화하지 않습니다.
- 복잡한 수식 설명, 복합 금액(예: 1억 2천만 원), 범위, 중첩 표와 목표·재원·기한의 정확한 관계는 자동 확정할 수 없습니다. 목표명·재원·기한은 텍스트 후보로 제공하며 수정·직접 추가가 필요할 수 있습니다.
- 기준일은 명시 문맥에서만 가져오며 날짜를 표준화하지 않습니다. 적용 기간과 시나리오는 원문 또는 사용자 입력 문자열입니다. 연결 제안은 금액 차이로 제거하지 않고 기준일·기간·시나리오 차이를 표시합니다. 제안은 동일성이나 오류의 판정이 아닙니다.
- 승인·수정 내역은 메모리에서만 유지됩니다. 새로고침·파일 교체 전에 필요한 작업을 마쳐야 합니다. 계산 검증·오류 판정·AI API는 미구현입니다.
- 파일 30MB, Excel 셀 100,000개, 읽은 XML 누적 100MB를 제한합니다. ZIP 엔트리의 압축 해제 후 용량을 검사하므로 악의적 압축 파일에 대한 완전한 메모리 보호 장치는 아닙니다. 대형 문서는 메인 스레드에서 처리되어 잠시 응답이 느려질 수 있습니다.

개인 샘플과 로컬 개발 지침·환경 파일은 `.gitignore`로 제외합니다.
