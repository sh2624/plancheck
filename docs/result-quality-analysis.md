# 자동 검수 결과 품질 분석

## 분석 조건

제공된 실제 XLSX·DOCX를 파싱·정규화하고, 앱과 동일하게 문서별 계획 후보를 추출한 뒤 사용자 승인 없이 자동 검사했다. 변경 전 분석을 먼저 수행했다. 개인 원문·파일명·경로는 이 문서와 저장소에 포함하지 않는다.

## 변경 전

| 유형  | 전체 | 수치 불일치·확인 필요 | 정보 부족·조건 보류 |
| ----- | ---: | --------------------: | ------------------: |
| CROSS |  188 |                   188 |                   0 |
| CALC  |   14 |                     8 |                   6 |
| PLAN  |   51 |                     6 |                  45 |
| ALLOC |    0 |                     0 |                   0 |
| 합계  |  253 |                   202 |                  51 |

사용자 승인 전 확정 오류와 검증 통과는 각각 0건이다. 자동 신호는 수치 차이 153건, 수치 일치 43건, 조건 확인 57건이었다.

CROSS 188건은 월 잉여금 20, 대출 잔액 18, 총자산 1, 총부채 1, 순자산 2, 대출 금리 3, 고정지출 40, 변동지출 28, 대출 상환액 8, 예금·적금 8, 연금 2, ETF 15, 저축·투자 15, 대출 기간 2, 소득 21, 보증금 4건이었다.

기존 공유 원본 그룹은 83개였고, 같은 원본을 공유하는 추가·파생 기록은 170건이었다. 이는 완전 중복이 아니다. 원본 쌍·관계·계산 범위·판정·근거까지 같은 완전 중복은 0건이었다.

보류 51건의 원인은 CALC 필수 입력 부족 6건(순자산 1, 대출 약정 5), PLAN 조건부 금액 해석 부족 29건, 시나리오·승인 조건 부족 6건, 제안·실행 짝 부족 16건이었다. 전체 후보의 확인 필요 이유는 중첩된다. 시나리오 미기재 192, 기준일 미기재 134, 기준일 문자열 차이 55, 기간 차이 77, 기간 미기재 18, 비확정 상태 195건이었다. 이 수치들은 합산할 수 없다.

## 확인한 오탐과 수정

- 예금과 적금 개별 항목, 예금·적금 합계의 범위를 혼합했다.
- 예금과 주식·ETF를 합친 금액을 ETF 단독 금액에 연결했다.
- 월세와 월세·관리비, 교통비와 통신·교통비 등 개별 지출과 묶음 지출을 연결했다.
- 자산 보유액과 월 적립액을 연결했다.
- 상환방식 선택 코드와 실제 월 상환액을 연결했다.

위 관계 59건(범위·역할 차이 53, 상환방식 코드 6)은 추천·승인 대상에서 제외했다. 원본 쌍과 제외 근거는 상세 분석 기록에 모두 보존하며 수치 비교 결과를 생성하지 않는다. 수동 연결과 인라인 승인에도 같은 제한을 적용한다. 원문 숫자나 파서의 항목 유형은 바꾸지 않았다.

Word 월 잉여금 추천에는 소계와 생활비 총계, 개별 상환액이 함께 포함되어 있었다. 저축 납입액이 자산 유형으로 추출된 경우 누락되기도 했다. 명시적인 포괄 총계는 단독으로 추천하고, 저축 역할이 모호한 경우 자동 계산·승인을 보류한다. 사용자 확인 없이 누락 항목을 재분류하거나 0으로 채우지 않는다.

253건을 모두 유지했다. 검증 엔진의 판정 상태와 화면의 우선순위는 별개다. 승인 전 확정 오류·통과는 여전히 0건이다.

| 화면 영역      | 기록 수 |
| -------------- | ------: |
| 우선 검토      |       7 |
| 추가 검토      |      21 |
| 상세 분석 기록 |     225 |

독립적인 우선 검토 항목은 월 잉여금, 학자금대출 잔액, 신용대출 잔액, 총자산, 총부채, 순자산, 신용대출 금리의 7건이다. 이 중 금리는 1.0%p, 학자금대출 잔액은 15,000원 차이 후보를 유지한다. 이는 동일 기준이라는 사용자 확인 전의 발견 후보다.

상세 분석 기록 225건은 첫 번째 분류 이유 기준으로 다음과 같다.

| 이유                                     | 기록 수 |
| ---------------------------------------- | ------: |
| 우선 발견을 지지하는 다른 원본·반복 기록 |       7 |
| 기간 충돌                                |      24 |
| 연도별 미래 계획과 현재 값 혼합          |      37 |
| 수치 일치 후보(자동 통과 아님)           |      40 |
| 개별·묶음 범위 또는 자산·납입 역할 차이  |      53 |
| 상환방식 코드                            |       6 |
| 계산 입력·구성 범위 부족                 |       7 |
| 조건부 금액 해석 부족                    |      29 |
| 조건부 시나리오 확인                     |       6 |
| 제안·실행 관계 부족                      |      16 |

우선순위는 핵심 항목 여부, 대출 대상 식별, 표·문맥·원본 근거, 단위와 적용 기간을 사용한다. 금액 차이 크기나 표시 개수 상한은 사용하지 않는다. 명시적으로 다른 조건과 비확정 정보는 확정 오류로 비교하지 않는다. 같은 수치 관계의 반복은 대표 발견과 지지 원본으로 구분하되 서로 다른 근거를 삭제하지 않는다.

## UI 변화

기존에는 202건의 확인 후보와 51건의 보류가 중심이었다. 이제 첫 화면은 7개 독립 발견의 제목·비교값·차이·검토 행동에 집중한다. 추가 검토와 상세 기록은 개수와 함께 접혀 있으며 재무 항목별로 필터링할 수 있다. 판정 코드와 반복 경고는 상세 근거로 이동했다. 부적합 연결은 비교 금액 대신 제외 이유와 원본 확인 버튼을 제공한다. 빈 필터 결과를 정상 판정으로 표시하지 않는다.

## 재현과 한계

검증 결과: 기존 137개를 유지한 전체 151개 Vitest 테스트가 실제 파일 환경변수와 함께 통과했다. Chrome E2E 7개도 통과했으며 금리·잔액 차이, 승인 후 판정 갱신, 원본 수정, 파일 교체 초기화, 중복 배정, 재무 항목 필터와 모바일 가로 넘침을 확인했다. 프로덕션 빌드와 린트는 통과했다. 린트에는 기존 TanStack Table의 React Compiler 호환성 경고 1건이 남아 있다.

README의 실제 파일 환경변수를 설정한 뒤 `npm test -- tests/result-quality-samples.test.ts`로 재현한다. `PLANCHECK_QUALITY_AUDIT=after`를 추가하면 비공개 원문이 포함된 로컬 감사 JSON을 `test-results/quality-after.json`에 생성한다. 이 폴더는 Git 제외 대상이며 Chrome E2E 실행 시 초기화된다. 공개 보고에는 집계만 옮긴다.

관계 검사는 제한된 한국어 항목 어휘와 문맥 규칙이다. 새로운 복합 항목, 같은 이름의 다른 계좌, 암묵적 시나리오는 사용자 확인이 필요하다. ‘상담 시점’ 같은 상대 기준일은 구체적 날짜 충돌로 단정하지 않는다. 다른 날짜 표기법을 임의로 동일시하지 않는다. 자산으로 분류된 납입액 자체를 자동 재분류하지 않으므로 상세 편집이 필요할 수 있다. PLAN·ALLOC의 누락 관계를 새로 추측하지 않으며, 미확인 검사를 통과 처리하지 않는다.
