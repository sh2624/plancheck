# 제출 전 질문 중심 UX 정리

## 화면 변경

| 영역           | 변경 전                                        | 변경 후                                                       |
| -------------- | ---------------------------------------------- | ------------------------------------------------------------- |
| 기본 수치 검토 | 적용·고급 편집·최종 조건·닫기 버튼을 함께 표시 | 핵심 질문·응답과 ‘답변 저장’ 우선, 고급 입력은 접힌 상세 영역 |
| 계획 관계      | 응답 버튼 선택 즉시 저장                       | 라디오 선택 후 공통 ‘답변 저장’으로 명시적 적용               |
| 계산 범위      | 검토 클릭 후 고급 구성·승인 입력부터 표시      | 구성 범위 질문부터 답변, 상세 편집은 별도 진입                |
| 저장 후        | 일부 답변 안내가 없거나 카드로 포커스 이동     | 저장된 답변·미확인 조건 안내로 포커스 이동, 다시 검토 가능    |
| 유형           | 규칙·제목으로만 구분                           | 문서 간 수치 차이 / 계산 결과 불일치 / 계획 확인 필요 표시    |
| 정상·보류 기록 | 일반 결과와 같은 제목 체계                     | 실제 차이가 없거나 통과한 기록에는 불일치 유형을 붙이지 않음  |
| 레이아웃       | 데스크톱 최대 1,440px                          | 최대 1,560px, 기존 모바일 여백·본문 14~15px·금액 강조 유지    |

원본·계산식·개별 규칙은 기존 판단 근거에 남는다. 같은 원인의 대표 카드와 개별 검사 근거 묶음도 유지한다. 새로운 금융 규칙·라이브러리·AI 기능은 추가하지 않았다.

## 조작 수와 상태 의미

검사 결과에서 해당 항목을 연 뒤 한 선택지를 선택하고 저장한다. 일반적인 기본 검토는 **열기 1 + 선택 1 + 저장 1 = 3회**다. 파일 선택기 내부 조작·업로드·검사 시작·원본 근거 펼치기는 이 수치에 포함하지 않는다.

- 수치 비교: 기존 3회 → 3회. 저장과 최종 승인의 시각적 혼동을 줄였다.
- 복합 관계: 기존 2회(열기·응답 즉시 적용) → 3회. 조작 수 감소는 아니며, 응답 선택만으로 저장되는 일을 막고 모든 유형의 저장 동작을 통일했다.
- 계산 범위: 기존에는 고급 승인 경로로 바로 진입했으나, 이제 3회로 검토 답변만 기록할 수 있다. 최종 승인과 동일한 작업이라고 비교하지 않는다.
- 이미 저장된 선택을 그대로 재저장하면 열기·저장 2회다.
- 고급 승인은 더 이상 기본 화면에 노출하지 않는다. 고정된 CROSS 승인 시연은 상세 열기 1회가 추가되어 4→5회다. CALC 고급 승인 시연은 3→5회다. 지급·수령·날짜 등의 실제 정보 확인 작업을 생략한 것이 아니다.

기본 저장은 기존 결정 모델과 원본 지문을 사용한다. CALC의 범위 질문도 같은 모델의 답변 기록이며 `scopeConfirmed=true`나 항목 확인 상태를 생성하지 않는다. 이미 승인된 계산에 대해 구성이 다름·모름으로 바꾸면 해당 계산의 `scopeConfirmed`만 해제한다. 같은 범위 답변이 미승인 계산을 승인하지는 않는다. 수치 비교는 기존 `recordOnly` 및 연결 승인 해제 경로를 유지한다. 파일 교체·원본 수정·응답 변경의 기존 무효화도 유지한다.

저장 시 안내에 포커스를 두며, 저장 없이 닫을 때는 카드에 돌려준다. Chrome 검증 중 저장 직후 카드로 돌아가는 예약 포커스가 안내를 화면 밖으로 미는 문제를 찾아 수정했다. 이는 화면 포커스만 조정하며 금융 상태를 변경하지 않는다.

## 정확도·화면 검증

- 기존 팀원 파일: 잉여금 2만 원·총자산 20만 원·예금 배정·조건부 금액·ETF 계획 5대상 유지.
- AFPK: 총자산 3,000만 원·연간 순현금흐름 120만 원 차이 유지. 동일 원인의 파생 근거와 정상·연결 제외 기록의 위치도 기존과 같다.
- 수치·계산·계획 질문의 저장 전후와 재열기, 원본 수정·파일 교체 시 무효화, 고급 최종 승인 경로, 승인 후 계산 범위 부정 응답의 승인 해제를 검사한다.
- 정상·허용오차 내 통과 결과를 불일치로 표시하지 않고 자동 발견을 확정 오류로 바꾸지 않는다.
- 1280px 데스크톱·390px 모바일에서 긴 텍스트·버튼·선택지의 가로 넘침과 겹침을 검사한다. 기존 Pretendard·남색·흰색·회색을 유지한다.

비공개 원본과 화면 캡처는 Git에서 제외한다. 변경 전후 캡처는 로컬 `.cache/submission-ux/`에 보관한다.

최종 검증은 전체 Vitest 48파일 **389개 통과**, Chrome **31개 통과·AI 모의 테스트 1개 제외**다. 마지막 재검토 진입 보완 후 관련 UI 16개와 실제 팀원·AFPK·모바일 Chrome 12개도 재확인했다. 빌드·포맷은 통과했고, 린트 오류 0개와 기존 TanStack Table 경고 1개다. 메인 JS 번들은 약 500kB로 Vite 크기 안내가 발생한다. 이를 감추기 위한 한도 변경이나 범위 밖 코드 분할은 하지 않았다.

## 변경 파일과 남은 한계

- `src/components/QuestionReview.tsx`: 기본 질문·선택·저장·접힌 상세 경로.
- `InlineReview.tsx`, `InspectionResults.tsx`: 기존 인라인·계산·계획 UI 연결, 저장 안내와 포커스.
- `src/presentation/findingGroups.ts`: 기존 결과에 따른 유형 표시만 추가.
- `src/App.tsx`: 계산 범위 부정·미확인 응답 시 기존 범위 승인 해제. 상태 타입을 새로 만들지 않음.
- `src/index.css`: 기존 스타일의 폭·유형 텍스트·선택지·상세 간격.
- UI 단위 테스트, 기존 E2E의 실제 새 동작과 조작 수, README·이 보고서를 갱신했다. 파서·정규화·검증 엔진·AI 설정은 변경하지 않았다.

최종 오류 확정에는 원문 기준·기간·확정 여부 등 기존 조건이 여전히 필요하다. 기본 답변 저장만으로 이 작업을 없앴다고 주장하지 않는다. 복잡한 계산 구성·대출 약정·계획 조건은 고급 화면에서 확인해야 한다. 저장 상태의 새로고침 범위도 기존 정책과 같다. 이 작업에서는 배포 환경을 수정하거나 push하지 않는다.
