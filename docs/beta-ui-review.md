# 베타 배포 전 화면 정리

## 변경 범위

기존 문서 등록 → 검사 결과 → 상세 검토 흐름을 유지한 UI 변경이다. 파서·정규화·계산·검증 엔진·자동 추천·결과 우선순위와 승인 상태 처리는 변경하지 않았다.

| 이전                                                | 변경 후                                                                                     |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 상단 오른쪽의 자물쇠·브라우저 처리 안내와 반복 안내 | 오른쪽 요소 제거. 파일 등록 영역 가까이에 개인정보 안내 한 번만 표시                        |
| 작은 본문·입력·보조 글씨                            | 페이지 제목 22~24px, 주요 제목 18px, 기본 본문 14~15px, 입력·버튼 14px 이상, 보조 설명 13px |
| 모바일의 일부 작은 버튼                             | 주요 버튼 높이 40px 이상, Tab 키 포커스 유지                                                |
| 확정 오류 / 자동 발견 / 정보 부족·보류              | 확인된 오류 / 검사 중 발견·확인 필요 / 추가 정보 필요                                       |
| 승인된 비교도 ‘확인 완료·확인 필요’로 혼동 가능     | ‘비교 기준 확인됨·확인 필요’로 남은 확인이 있음을 표시                                      |
| 화면마다 다른 원본 수정 버튼 명칭                   | ‘문서 내용 확인·수정’으로 통일                                                              |
| 정규화:                                             | 상세 편집의 표시 문구를 ‘단위를 맞춘 금액:’으로 변경                                        |
| 단계 안내와 포커스 테두리가 붙는 좁은 간격          | 안내 위 간격 확보. 섹션 24px, 관련 요소 8~16px, 내부 여백 16~24px 중심으로 정리             |

Pretendard Variable의 로컬 파일과 기존 남색·흰색·회색을 유지했다. 새 폰트·UI 라이브러리·장식 아이콘은 추가하지 않았다. 금액에는 기존 포맷터와 tabular-nums를 유지하며 원본 값과 단위는 변경하지 않는다.

‘확인된 오류’는 기존 엔진의 사용자 확인 후 오류 상태를 표시하는 용어다. ‘검사 중 발견·확인 필요’는 확정 판정이 아니다. 내부 데이터 모델의 `오류`, `확인 필요`, `검증 통과`, `검증 불가` 값은 그대로다. 중요한 범위·단위·기준일 확인과 수식 재계산 제한 안내는 삭제하지 않았다. 검증 코드·추출 신뢰도·상세 계산 과정은 펼쳐보기와 고급 화면에서 계속 확인한다.

## 화면 점검

`e2e/beta-ui.spec.ts`가 실제 XLSX·DOCX 바이트에 긴 한글 파일명을 붙여 브라우저에 등록한다. 1280px 데스크톱과 390px 모바일에서 파일명 줄바꿈, 문서 내용·긴 문장, 원본 펼치기, 페이지 가로 넘침, 글자 크기, 버튼 높이와 Tab 포커스를 확인한다. 화면 결과를 바꾸는 가짜 데이터나 DOM 교체는 사용하지 않는다.

기존 회귀 테스트는 삭제하지 않았다. 변경된 화면 문구에 해당하는 기대 문자열·버튼 이름만 갱신했으며, 수치 차이·확인 전후 판정·원본 표시·파일 교체 초기화·중복 배정과 조작 횟수에 대한 검사는 유지한다.

최종 결과: Vitest 164개, Chrome E2E 13개가 실제 문서 환경변수와 함께 모두 통과했다. 프로덕션 빌드·린트·Prettier 검사를 통과했으며, 기존 TanStack Table 경고 1건은 남아 있다. 1280px·390px 스크린샷을 확인했고 긴 한글 파일명과 문서 내용에 페이지 가로 넘침이 없었다.

## 남은 한계

고급 편집과 원본 표는 정보가 많아 기본 화면보다 밀도가 높으며, 넓은 표는 해당 표 영역 안에서 스크롤한다. 이번 화면 정리가 추출·검증 정확도의 한계를 해결한 것은 아니다. 실제 기기·다른 브라우저의 전체 조합을 검사하지 않았으며, Chrome의 위 두 너비와 기존 시연 흐름을 검증 범위로 삼았다. 기존 TanStack Table의 React Compiler 호환성 린트 경고는 유지한다.
