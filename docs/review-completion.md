# 일반 검토 완료 경험 최종 점검

## 수정 범위

새 기능·버튼·설정·검증 규칙을 추가하지 않았다. 기존 답변 결정에 대한 표시만 정리했다. 파서·정규화·검증 엔진·승인 모델·파일 초기화·AI 설정은 변경하지 않았다.

| 단계                       | 수정 전                                     | 수정 후                                                   |
| -------------------------- | ------------------------------------------- | --------------------------------------------------------- |
| 미응답                     | 질문과 ‘이 항목 검토’                       | 동일                                                      |
| 같은 기준·관계 답변 저장   | 답변 기록/비교 조건 미확인/확인 필요가 혼재 | ‘일반 검토 완료 · 오류 미확정’                            |
| 모름 답변 저장             | 계속 확인 필요로 보임                       | ‘일반 검토 완료 · 판단 보류’                              |
| 이미 답한 카드             | 같은 질문과 검토 버튼이 반복됨              | 저장한 선택지를 표시하고 기존 버튼을 ‘답변 수정’으로 변경 |
| 저장 안내                  | 상세 조건 입력을 계속 요구하는 인상         | 저장한 답변·최종 판정·선택적 다음 행동을 분리             |
| 기존 확정 판정이 있는 응답 | 기존 판정 유지                              | 기존 엔진 결과에 따라 확인된 오류/검사 통과를 표시        |

‘일반 검토 완료’는 질문에 답변해 저장했다는 뜻이다. 원문 조건·날짜·단위·확정 여부·지급 승인을 확인 완료로 바꿨다는 뜻이 아니다. ‘아니요’나 ‘모름’도 답변 저장은 완료되지만 사실 판단이나 오류 확정은 보류한다. 정상 판정으로 바꾸지 않는다.

사용자에게는 다음을 안내한다.

1. **저장한 답변:** 선택한 실제 문구를 그대로 표시한다. 예: 같은 예금을 동시에 사용한다는 답변.
2. **오류 확정 여부:** 미승인 결과는 오류 미확정, 모름은 판단 보류다. 기존 승인 오류·통과는 실제 엔진 상태대로 표시한다.
3. **다음 행동:** 추가 입력 없이 일반 검토를 마칠 수 있다. 최종 판정이 필요한 경우에만 기존 상세 검토를 이용한다.

고급 조건이 부족하다는 이유로 일반 검토를 미완료로 표시하지 않는다. 다만 원본의 미기재 조건과 기존 계산 근거는 상세에서 그대로 확인할 수 있다. 질문은 답변 수정으로 다시 열었을 때만 표시한다. 기존 저장 후 포커스 안내와 선택값 복원도 유지한다.

## 조작 수와 상태 유지

- 첫 일반 검토: 열기 → 선택 → 답변 저장, **3회**로 기존과 같다.
- 이미 저장된 답변을 그대로 다시 저장: 답변 수정 → 답변 저장, **2회**다.
- 답변 변경: 답변 수정 → 새 응답 선택 → 답변 저장, **3회**다.
- 파일 선택기·업로드·검사 시작·근거 펼치기는 위 횟수에 포함하지 않는다.
- 응답 수정·파일 교체·원본 변경의 기존 승인 해제·지문 무효화를 유지한다. 미확인 정보를 채우거나 저장 선택지만으로 오류를 확정하지 않는다.

## 실제 파일·회귀 검증

비공개 팀원 XLSX·DOCX에서 기존 잉여금·총자산·예금 배정·조건부 금액·ETF 계획의 다섯 검토 대상을 확인한다. AFPK 파일에서는 총자산 3,000만 원과 연간 순현금흐름 120만 원 차이를 확인한다. 새 결과를 만들거나 원본을 수정·전송·커밋하지 않는다.

단위 회귀는 모든 선택값에 대해 원본 값·기준일·확정 여부·승인 상태가 변하지 않는지 확인한다. 미응답 결과에는 완료 표시가 없고, 기존 오류·통과 상태는 그에 맞게 표시하는지 검사한다. Chrome에서는 저장된 답변과 완료 안내, 답변 재열기, 고급 승인, 부정 응답의 승인 해제, 파일 교체 후 초기화와 원본 근거 접근을 검사한다. 상태 문자열을 바꾼 테스트도 같은 판정·원본 보존 검사를 유지한다.

응답 전후 실제 Chrome 화면은 Git에서 제외한 `.cache/review-completion/before-answer.png`, `after-answer.png`에 보관한다. 캡처는 같은 팀원 문서 세션에서 총자산 질문에 답변하기 전후다. 다른 항목의 기존 답변이 함께 표시될 수 있다.

## 남은 한계

완료 표시는 앱의 현재 유효한 답변 결정에 한정된다. 새로고침·세션 보존 범위는 기존 정책과 같고, 파일을 교체하거나 원문을 수정하면 다시 답해야 할 수 있다. 상단 발견 수는 미응답 과제 수가 아니라 발견 대상 수이며, 완료 상태는 각 카드에서 구분한다. 모든 질문에 답해도 문서 전체의 정상이나 모든 오류의 확정을 뜻하지 않는다. 최종 판정에 원본 기준·기간·확정 여부가 필요하면 기존 고급 검토 조건은 그대로 적용한다.

## 최종 결과와 변경 파일

- 전체 Vitest 49파일 **393개 통과**(기존 389개 유지, 완료 표시 회귀 4개 추가).
- 전체 Chrome **31개 통과**, Production 비활성 상태의 AI 모의 테스트 1개 제외.
- 대표 묶음 중 실제 답변한 검사의 문구를 선택하는 마지막 보완 후 관련 단위/UI 16개와 실제 파일 Chrome 12개도 재확인했다.
- 프로덕션 빌드·포맷 통과. 린트 오류 0개, 기존 TanStack Table `react-hooks/incompatible-library` 경고 1개 유지.
- 상태 표시·저장 안내는 `src/components/InspectionResults.tsx`, 표시용 순수 함수는 `src/presentation/reviewCompletion.ts`에 한정한다. 승인 모델과 App의 데이터 처리 코드는 변경하지 않았다.
- `tests/review-completion.test.ts`, 기존 복합 UI 테스트와 Chrome 회귀의 문구·동작 검사를 갱신했다. 저장 문구의 이전 부분 문자열 대신 실제 저장한 응답 전체를 검사한다.

원본 금융 문서·화면 캡처는 커밋하지 않는다. 로컬 커밋 해시는 완료 보고에 기록하며 push·배포는 하지 않는다. 실제 Production 배포 후 사용자 흐름 확인은 별도 단계다.
