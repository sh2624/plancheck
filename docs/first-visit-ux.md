# 첫 방문 화면 정리와 배포본 직접 점검

## 수정 범위

- 문서도 수동 입력도 없는 고급 화면에서는 초기 계산 명세의 ‘검증 불가 5건’과 기본 추천 수를 표시하지 않는다. 등록 안내에서 실제 Excel 입력으로 이동해 초점을 맞춘다.
- 문서 등록 후의 기존 고급 설정·수동 입력 경로와 검증 엔진·승인 모델은 유지한다.
- 파일 선택 전에 Excel 수식을 재계산하지 않는다는 제한과 최신 계산 결과 저장 안내를 표시한다.
- 상단 상세 검토에 ‘선택’을 표시한다. 모바일 단계 버튼의 간격을 조정한다.
- 간략 업로드 카드의 미등록 안내 중복·빈 여백을 줄인다. 파일 처리·실패·초기화 안내는 유지한다.
- 상세 검토의 핵심 안내는 한 문장으로 줄이고 편집 조건·전체 목록 설명은 접을 수 있는 안내로 옮긴다.

## 배포본 직접 확인

2026-11-13 https://www.plancheck.cloud/ 에서 기존 비식별 테스트 생성기로 만든 가상 XLSX·DOCX를 실제 파일 선택기로 등록했다. 실제 팀원·AFPK 원본은 공개 사이트에 등록하지 않았다.

1. 두 문서의 ‘등록 완료 · 추출됨’과 검사 시작 활성화를 확인했다.
2. 검사 시작 한 번으로 Excel 잉여금 7만 원, Word 9만 원, 차이 2만 원을 자동 발견했다.
3. 원본 근거에서 가상 파일명·Excel 재무현황!B5·Word 본문 표 1의 위치와 원문을 확인했다.
4. 같은 기준 답변 저장 후 ‘일반 검토 완료 · 오류 미확정’, 답변 수정 시 선택값 복원을 확인했다.
5. 모름으로 변경·저장한 뒤 ‘일반 검토 완료 · 판단 보류’와 확인된 오류 0을 확인했다. 별도 계산 검토 후보는 유지됐다.

이 확인은 배포되어 있던 기존 버전의 가상 문서 흐름 점검이다. 새 수정본의 Production 확인이나 실제 AFPK 문서 전체 성능의 증거로 대체하지 않는다. 외부 전송 여부에 대한 전체 네트워크 감사도 아니다.

## 수정본 직접 확인

로컬 빌드에서 문서 없는 고급 결과의 등록 안내, 수식 제한 상시 노출, 모바일 390×844의 한 줄 단계 버튼과 압축 업로드 카드를 확인했다. 가상 문서 등록→검사→같은 기준 답변 저장까지 직접 수행했다. 결과·검토 화면의 문서 가로 폭은 뷰포트 이하였으며 카드와 저장 안내를 읽을 수 있었다. 실제 휴대전화 파일 선택기는 별도 확인 대상이다.

## 검증 결과

- 실제 기본·팀원·AFPK 문서 경로를 지정한 Vitest 49파일 393개 통과.
- 기존 Chrome 흐름 30개 통과, AI 비활성 테스트 1개 제외. 실패한 1개는 자료 없는 화면에서도 오류 0·준비 중 5건을 기대하던 이전 동작의 테스트였으며, 새 등록 안내·결과 수 미노출·파일 입력 초점 검사로 갱신했다. 갱신한 검사를 단독 재실행해 1개 통과했다. 합산 Chrome 31개 통과, AI 1개 제외다. 마지막 모바일 버튼 간격 조정 후에는 로컬 빌드와 직접 모바일 등록·검사·답변 저장을 재확인했다.
- 빌드 통과. 500kB 초과 번들 안내와 기존 TanStack Table 린트 경고 1개가 있다. 린트 오류 0개, 포맷 검사 통과.
- 파일 원본은 수정·커밋하지 않았다. push·배포하지 않았다.
