# 최종 결과 화면 UX 정리

2026-11-12, 로컬 검증. 검사 흐름은 **Excel·Word 등록 → 준비 완료 → 검사 시작 → 결과 → 필요한 조건만 검토**로 유지한다. 파서·단위 상속·자동 매칭·CALC·CROSS·ALLOC·PLAN·승인/무효화 모델·AI 설정은 변경하지 않았다.

## 실제 팀원 파일의 다섯 결과

| 대상        | 기본 표시                                                                  | 판정 경계                                   |
| ----------- | -------------------------------------------------------------------------- | ------------------------------------------- |
| 잉여금      | Excel 9만 원, Word 7만 원, 차이 2만 원                                     | 비교 기준 확인 전 자동 오류 확정 아님       |
| 총자산      | Excel 3,090만 원, Word 3,070만 원, 차이 20만 원                            | Word 표·문단 근거는 대표 발견의 상세에 보존 |
| 예금 배정   | 보유 590만 원, 배정 총 890만 원, 같은 시점 사용 시 300만 원 부족           | 같은 자금·사용 시점·보유액 기준 확인 필요   |
| 조건부 금액 | 월세 세액공제 예상액 132만 원, 정부기여금 금액 미확인, 미래 자산 포함 문맥 | 미래 예상 자산 반영 자체는 오류가 아님      |
| ETF 계획    | 4단계 월 15만 원 적립 중단 제안, 5단계 월 15만 원 자동이체 유지            | 같은 ETF·동일 적립·기간인지 확인 필요       |

새 값을 추출하거나 결과를 재계산한 것이 아니다. 기존 구조화 값과 원본 참조를 읽는 표시 함수로 요약한다. 정부기여금의 금액을 0으로 만들지 않으며, 단계 제목이 원본에 없으면 제안/실행만 표시한다.

## 기본 화면과 상세 화면

기본 목록은 제목, 핵심 값, 차이/의미, 한 문장 질문과 검토 버튼으로 구성한다. 원문 문장·파일명·셀/문단 위치·규칙 코드·신뢰도·계산식·전체 분석 기록은 기존 펼쳐보기 안에서 보존한다. 동일 발견의 대표 그룹화는 변경하지 않았다.

‘이 항목 검토’를 누르면 해당 질문의 선택지만 펼친다. 지급·수령 등 별도 정보나 최종 오류를 승인하지 않는다는 안내는 이 편집 영역에만 표시한다. 복잡한 변경은 기존 상세 조건 화면으로 이동한다. 응답 후 목록에서 보류 항목이 이동하더라도 상태 안내와 ‘이 답변 다시 검토’로 접근할 수 있다. 오래된 답변은 기존 원본·값·계획 지문 검증에 의해 무효화되며, 무효화된 답변의 안내도 표시하지 않는다.

## 맞춤 질문과 기존 결정 값

| 대상        | 질문                                                                         | 예 → `same`                          | 아니요 → `different`                     | 모름 → `unknown`    |
| ----------- | ---------------------------------------------------------------------------- | ------------------------------------ | ---------------------------------------- | ------------------- |
| 예금        | 두 목표에 같은 예금을 같은 시점에 사용하나요?                                | 예, 같은 자금입니다.                 | 아니요, 다른 자금이거나 시점이 다릅니다. | 확인할 수 없습니다. |
| 조건부 금액 | 이 금액은 지급·수령 조건이 확정되었고, 표시된 시점에 반영 가능한 금액인가요? | 예, 조건과 반영 시점이 확인됐습니다. | 아니요, 아직 확정되지 않았습니다.        | 확인할 수 없습니다. |
| ETF         | 두 계획은 같은 ETF의 동일 기간 적립을 말하나요?                              | 예, 같은 ETF와 기간입니다.           | 아니요, 상품이나 적용 기간이 다릅니다.   | 확인할 수 없습니다. |

여기서 `same`은 질문에 대한 긍정 답변의 기록이며 개별 날짜·지급 승인·수령 상태를 채우지 않는다. 조건부 금액의 `different`는 이번 질문의 부정 답변으로 기존 보류 분류를 사용하며, 화면에는 ‘미확정 답변’이라고 표시한다. 다른 상품으로 잘못 설명하지 않는다. `unknown`은 답변 보류다.

예 응답 후에는 ‘답변 기록 · 확인 필요’를 표시하고 실제 적용일 등 남은 필수 입력을 안내한다. 아니요/모름은 상세 분석 기록으로 보류하며 원래 발견과 근거를 삭제하지 않는다. **실제 팀원 파일의 9가지 응답 모두 확정 오류 0개를 유지했다.** 최종 판정은 기존 상세 확인·승인과 엔진 조건을 충족해야 한다. 하나의 복합 응답으로 개별 지급·수령·날짜가 모두 확인됐다고 간주하지 않는다.

## 타이포그래피와 스크린샷

Pretendard와 남색·흰색·회색을 유지한다. 주요 제목 17~18px, 값 20px, 본문 15px/약 1.55, 질문·버튼 14px 이상, 보조 설명 13px로 정리했다. 긴 응답 버튼은 여러 줄로 확장되고 키보드 포커스·선택 표시를 유지한다. 장식·새 라이브러리는 추가하지 않았다.

실제 팀원 파일을 사용한 로컬 Chrome 스크린샷이며 금융 정보가 있으므로 저장소에는 포함하지 않는다.

- 노트북 1280px: `.cache/results-ux/results-laptop.png`
- 모바일 390px: `.cache/results-ux/results-mobile.png`
- 모바일 확인 영역: `.cache/results-ux/review-mobile.png`

기본 근거가 접힌 상태, 다섯 대표 항목, 비교값과 행동, 긴 버튼의 줄바꿈을 확인했다. 가로 넘침이 없고 응답 버튼의 경계가 겹치지 않는지 DOM 크기도 검사했다.

## 남은 사용성 한계

긴 목록은 모바일에서 세로 스크롤이 필요하다. 복합 응답 기록과 최종 승인 모델은 여전히 별도이므로 날짜·지급 조건이 부족하면 상세 검토가 필요하다. 같은 원문의 혜택 두 개를 한 문맥으로 요약해도 각 혜택의 승인·금액은 합치지 않는다. 이번 작업에서는 이 한계를 숨기거나 검증 조건을 완화하지 않았다.

기본 화면 간소화를 위해 복합 관계에 답변하려면 검토 열기와 응답 선택의 2회 클릭이 필요하다. 새로운 검증 기능은 추가하지 않았고 원격 push·배포도 수행하지 않는다. 이후에는 신규 기능 개발 대신 Production 배포 점검으로 진행한다.
