# 제출 전 사용자 피드백 반영

## 기준과 범위

정상 기준은 `d7e348b`이며 로컬 태그 `baseline-before-hybrid-20261112`로 보존했다. 별도 기준 체크아웃에서 같은 팀원 원본을 읽기 전용으로 실행한 후 임시 체크아웃을 정리했다. 기준 태그는 유지한다. 원본 XLSX·DOCX는 `docs`에 있지만 Git 제외 대상이며 외부 AI에 보내지 않았다. 이 문서에는 원문·고객명·파일명을 싣지 않는다.

## 1단계: 실제 원본과 재현 구조의 평가

팀원 원본을 확보했다. ‘재현 구조만 검사했다’는 결과와 구분하며, 실제 파일 테스트는 `PLANCHECK_TEAM_XLSX`·`PLANCHECK_TEAM_DOCX` 환경변수로 재현한다. 원본의 메모리 복사본을 파싱하고 실행 전후 파일 바이트의 동일성을 검사한다.

| 평가                           | 기준 버전                       | 개선 후                                                         |
| ------------------------------ | ------------------------------- | --------------------------------------------------------------- |
| 팀원 Word·Excel 월 잉여금 차이 | 단위·문장 위치 누락으로 미발견  | 9만 원과 7만 원의 2만 원 차이 자동 발견                         |
| 팀원 Word 월 잉여금 재계산     | 지출·저축·잉여금 문장 누락      | 소득−지출−저축 = 9만 원, 보고 7만 원의 2만 원 차이 자동 발견    |
| 팀원 총자산 차이               | Excel 헤더 단위 누락으로 미발견 | Excel 3,090만 원과 Word 3,070만 원의 20만 원 차이 자동 발견     |
| Excel 자산 구성                | 청약저축 누락                   | 청약저축을 포함한 구성 합계 3,090만 원과 보고값 일치            |
| 핵심 두 오류 계열 자동 발견    | 0/2                             | 2/2 (계산·표·문단의 반복 근거를 별도 오류로 중복 계산하지 않음) |
| 확인 전 확정 오류              | 0                               | 0. 모든 발견은 원문 조건 확인 전 후보 상태                      |

기준 버전의 추출 항목은 20개, 개선 후 25개다. 숫자 차이 분석 기록은 1개에서 6개로 바뀌었다. 6개는 잉여금 계산·교차 비교 2개, 총자산 문단·표 비교 2개, 파생 순자산 1개, 미래 자산 비교 기록 1개다. 기록 수 자체를 독립 오류 개수나 정밀도로 해석하지 않는다.

기준 버전에서 불완전한 Word 자산 표를 전체 구성처럼 계산해 표시하던 2,480만 원 차이는 범위 확인으로 보류한다. 청약저축과 일반 예금을 서로 연결하는 두 후보는 비교에서 제외하고 기록을 유지한다. 1년 후 자산은 현재 자산과 같은 기준의 우선 오류처럼 비교하지 않는다. 나머지 계획 관계는 기간·승인 정보가 없어 이번 규칙 기반 단계에서 확정하지 않는다.

별도 비식별 재현 문서는 ‘항목 | 금액(만원)’ 구조다. 월 잉여금 계산·교차 차이와 총자산 계산·교차 차이가 기준 버전에서는 모두 계산 불가였고 개선 후 발견된다. 두 정상 대조본은 차이 0이며 자동으로 ‘통과’ 확인을 부여하지 않는다. 이 결과를 팀원 원본의 평가와 섞지 않는다.

### 수정 원인

- 시트 단위, 표 제목, 병합·다중 열 헤더, 명시 셀 단위의 출처를 보존했다. 단위 선언끼리 충돌하면 값을 비우며 셀의 명시 단위를 우선한다. 표 사이에 열 단위가 새지 않도록 경계를 구분한다.
- 빈 행 뒤에도 명시된 시트 단위와 월·연 현금흐름 열의 의미는 보존한다. 보증금의 ‘월세’를 월간 금액으로 해석하지 않는다.
- Word 문장의 마침표 뒤 상대 문자 위치 계산을 바로잡았다. 월 지출·저축·잉여금과 청약저축 명칭을 인식한다. ISO 날짜를 지원금 금액 범위로 혼동하지 않는다.
- 합계·소계·전체 월 지출과 개별 지출의 범위를 보존한다. 금액 유사도는 관계 확정에 사용하지 않는다. 기본 검증 엔진의 수식과 최종 판정 규칙은 유지한다.
- 명확한 관계는 자동 비교 후보로 구성하지만 승인 링크나 확정 사실을 생성하지 않는다. 필요한 기준일·시나리오·확정 여부는 사용자가 확인한다.

### 사용자 조작

두 핵심 오류의 자동 발견까지 필요한 추가 확인은 개선 후 0회다(두 파일 등록·검사 시작 제외). 기준 버전에서는 발견 자체가 안 돼 동등한 조작 수를 산출하지 않는다. 단위가 없는 별도 재현 문서는 상세 검토 이동 → 범위 편집 펼치기 → 표 선택 → 단위 선택 → 적용 → 결과 복귀의 6개 조작으로 4개 값에 단위를 적용한다. 셀의 명시 단위는 보호하고 확인 상태·관련 승인을 해제한다. 사용자 확인이 없는 값은 확정 오류로 처리하지 않는다.

### 남은 한계

1단계 검증: 기존 164개를 포함한 182개 테스트, 기존 Chrome 흐름과 신규 단위·팀원 검사 경로가 통과했다. 빌드·린트를 통과했으며 기존 TanStack Table 경고 1건은 유지한다. 원본 파일은 커밋에서 제외했다.

팀원 자료에는 기준일·시나리오·일부 계획 기간이 없어 최종 판정에 추가 확인이 필요하다. 자연어 문맥을 모두 이해하는 파서는 아니며, 표 경계가 불명확하거나 상충한 단위는 범위를 직접 지정해야 한다. 지원하지 않는 복합 단위·복잡한 병합 표는 원본과 대조해야 한다. 개선 효과는 이 원본 한 쌍과 재현 구조에 대한 결과이며 모든 문서에 대한 100% 검출률이 아니다.

## 2단계 — 선택형 AI Preview 준비

`/api/analyze-context`와 선택 전송 UI를 분리해 구현했다. 서버는 Preview 환경·활성 플래그·서버 키를 모두 요구하며, 기본 UI와 Production 서버는 비활성이다. 명시적 동의 후 선택한 문장과 임시 ID만 보내고 원본 파일명·전체 파일은 보내지 않는다. strict Structured Outputs 응답도 출처·인용·숫자·단위 결합·행동·시점의 원문 일치를 재검사한다. 부정된 행동, 출처 없는 값, 불완전·거부 응답은 채택하지 않는다.

AI 제안은 별도 영역에 표시하고 사용자가 가져오기를 눌러야 미확인 계획 행에 추가된다. 대상 ID·기간·승인·수령 여부는 임의로 채우지 않으며 기존 검증 엔진의 확인 절차를 유지한다. 원문 일치는 관계의 의미가 사실이라는 증명이 아니다. 배정 대상이나 행동을 모두 안전하게 연결하는 자동 승인 기능은 구현하지 않았다.

### 비교 결과와 채택 결정

| 항목                           | 규칙 개선 전                | 규칙 개선 후                | AI 보조         |

실제 Preview 주소가 제공되지 않아 배포·라이브 API 검증은 수행하지 않았다. 사용자 요청대로 원격 push·배포는 수행하지 않는다. 따라서 AI 효과가 확인되었다고 주장하지 않으며 **최종 Production에는 AI를 활성화하지 않는다**. 보호된 Preview에서 합성 자료 평가 후 유지 여부를 결정한다. [배포·실험 안내](ai-preview.md)에 설정과 평가 스크립트를 제공했다.

추가 안전성/UI 테스트 24개를 포함한 전체 206개 테스트가 통과했다. Chrome AI 테스트 1개는 실제 모델이 아닌 모의 API 응답으로 선택·동의·제안 표시·미확인 가져오기·파일 교체 초기화를 확인했다. 기본 비활성 빌드에서는 기존·피드백 흐름 17개가 모두 통과했고 AI 전용 1개는 의도적으로 건너뛰었다. 빌드·포맷·린트는 통과하며 기존 TanStack Table 경고 1건이 남아 있다.

### 남은 운영 제한

요청당 입력/출력·예상 비용·타임아웃은 제한했지만 서버리스 인스턴스 간 누적 지출 상한은 없다. 보호된 Preview 접근과 OpenAI 프로젝트 사용량 관리가 필요하다. 가격·모델 가용성과 실제 Vercel 라우팅·서버 키 설정·응답 시간은 배포 후 확인해야 한다. 실제 금융자료는 AI 실험에 사용하지 않는다. 문장에 개인정보가 포함될 수 있어 선택 화면에서 직접 확인해야 한다.

## 복구와 비공개 자료

작업을 버리지 않고 기준을 확인하려면 `git switch --detach baseline-before-hybrid-20261112`, 현재 개발로 돌아오려면 `git switch main`을 사용한다. 실제 배포 복구는 Vercel의 이전 배포를 선택한다. 원격 push와 배포는 사용자가 수행한다.

`docs/*.xlsx`, `docs/*.docx`, `.cache`, `test-results`, 환경변수 파일은 커밋하지 않는다. 실제 원문이 포함된 로컬 측정 JSON도 공개하지 않는다.
