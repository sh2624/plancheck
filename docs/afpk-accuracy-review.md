# AFPK 형식 정확도 회귀 검증

## 원본과 기준선

2026-11-13 제공된 비공개 AFPK XLSX·DOCX를 직접 읽었다. 원본은 외부 전송·변경·Git 추가하지 않았다. 테스트 전후 파일 바이트 동일성을 검사한다. 실행 경로는 `PLANCHECK_AFPK_XLSX`, `PLANCHECK_AFPK_DOCX`로 전달하며 제품 코드에서 파일명·숫자를 분기하지 않는다. 문서 내용은 검사 대상이며 실행 지시로 사용하지 않는다.

복구 태그 `baseline-before-afpk-20261113`은 수정 전 `d85f0c2`를 가리킨다. 기존 복구 태그도 유지한다. 수정 전 전체 추출·검사 결과는 비공개 로컬 `.cache/afpk/before.json`, 수정 후 결과는 `after.json`에 보관하며 저장소에서는 제외한다.

실제 Excel은 재무상태표·현금흐름표·재무비율 3시트이고 금액 열은 각 표에서 하나다. Word는 문단 9개와 요약표 1개이며 실제 총자산 표기는 **23,000만 원**이다. 이 제공본에는 억·만 복합 표기나 만원·억원 이중 열이 없다. 따라서 이 두 구조는 원본을 고친 복사본이 아니라 별도의 비식별 OOXML 재현 테스트로 검증했다. CMA·IRP도 재현 테스트이며 실제 제공본의 입출금통장·연금저축·카드 미결제액과 구분한다.

총 추출 후보는 22개 → 42개, 전체 검사 기록은 16개(CROSS 7 / CALC 9) → 44개(CROSS 32 / CALC 12)다. 잘못 대응되는 항목을 제외한 기록·정보 부족 기록도 보존하므로 이 수치는 오류 개수가 아니다. 비영 차이 기록은 6개 → 8개이며, 수정 전에는 위 Excel 오탐 2개가 포함됐다. 수정 후 비영 기록은 총자산·순자산·연간 흐름의 비교 및 계산 근거이며 문단·표의 반복 위치가 포함된다. **자동 확정 오류는 전후 모두 0개**다.

## 구현과 안전 조건

- 억·만 원을 하나의 통화 토큰으로 읽고 원 단위 편집 숫자로 정규화한다. 원문과 원본 위치는 유지한다. 부호·쉼표를 검사하고 잘못된 하위 단위는 미확인으로 남긴다. 날짜·금리·개월은 금액과 구분한다.
- 동일 행의 항목·금액 역할·기간·기준·시나리오가 일치하고 서로 다른 단위 열의 값이 동등한 경우만 계산 대표를 한 번 선택한다. 두 셀 모두 후보로 유지하고 대표 셀·나머지 표현·원본 참조를 근거에 남긴다. 다른 금액 역할이나 동일 단위의 별개 열은 제거하지 않는다. 값이나 조건이 다르면 후보에 불일치를 기록하고 관련 계산을 보류한다. 편집 시 현재 값을 다시 검사한다.
- 입출금통장·CMA는 예금 계열, 연금저축·IRP는 연금 계열, 카드 미결제액은 부채 잔액 계열로 분류한다. 상품의 명시적 납입·지출 역할은 별도로 분류하며, 이체액만 명시되어 자산 이동인지 저축인지 불명확하면 숫자와 역할을 보존한 미분류 후보로 둔다. 입출금통장과 정기예금, 근로소득·기타소득·총유입의 잘못된 자동 대응은 막는다.
- 월·연 기간은 열 제목·항목명·해당 연간 현금흐름 문단의 명시 범위에서 보존한다. 기존 잉여금 식을 동일한 연간 입력에도 적용한다. 소계와 구성 항목을 함께 더하거나 총유출에서 저축을 다시 차감하지 않는다. 이번 실제 Word 계산은 총유입에서 고정·변동 지출과 저축을 각각 한 번 차감하며, 그 합이 원문 총유출 4,440만 원이다.
- 서로 다른 월·연 기간의 비교는 양쪽 원문에 반복 금액이라는 근거가 있는 흐름에만 연간 기준 ×12를 적용한다. 원본 숫자와 배수는 판단 근거에 보존한다. 일회성·기간 미확인 값에는 적용하지 않는다. 기준일·시나리오·사용자 확인 등의 기존 최종 판정 조건은 유지한다.
- UI·파일 등록→검사 시작 흐름·사용자 확인 모델·AI 비활성 설정은 바꾸지 않았다. 외부 API 호출이나 Production 배포는 하지 않는다.

## 검증 범위와 한계

- 재현 OOXML 테스트: 복합 통화 6표현의 본문·표 경로, 부호·오류 단위·날짜·금리 제외, 동등·불일치 단위 열, 별개 금액 역할, 자산·부채·순자산·잉여금 중복 합산 방지, 5계정의 잔액과 납입 구분, 월·연 태그, 반복 환산과 일회성 제외를 검사한다.
- 실제 AFPK: 추가 단위 지정·연결 승인 없이 검사 시작 1회로 연간 120만 원·자산 3,000만 원 차이와 실제 문단의 계산 근거를 Chrome에서 확인한다. 원본 파일은 변경하지 않는다.
- 기존 팀원: 잉여금 2만 원, 총자산 20만 원, 예금 배정, 조건부 금액, ETF 행동의 5검토 대상 유지 및 미확인 상태·파일 교체 초기화를 회귀 검사한다.
- 확인한 실제 AFPK 정상 자산·부채·순자산·현금흐름 계산의 새 오탐은 없다. 모든 문서의 무오탐·무미탐을 보장하는 평가는 아니다. 불명확한 자연어·완전하지 않은 자산 목록·반복성이 명시되지 않은 월·연 관계는 계속 확인 대상이다.
- 요약표에 세부 구성이나 기간이 없으면 단독 계산을 보류하고 본문 계산 근거를 유지한다. 이를 통과로 바꾸지 않는다.
- 재무비율의 40%와 34.8% 같은 차이는 이번 작업에서 새로 지원하지 않았다. 일반 비율 항목 분류나 DSR 규제 계산은 추가하지 않았다. 기존 대출 금리 비교는 유지한다.
- 원본이 없는 ‘미기재 단위’와 복잡한 화폐 표현 전반을 추측하지 않는다. 한글 수사·통화 외 억/만 수량·한 토큰 안의 복수 통화·암묵적 반복성은 지원 범위가 아니다.

## 최종 실행 결과

- Vitest 전체 46파일 **375개 통과**. 기존 347개를 유지하고 AFPK 정규화 재현 27개와 실제 파일 통합 1개를 추가했다.
- 실제 Chrome 전체 **31개 통과**, AI 비활성화로 Preview 모의 API 테스트 1개 건너뜀. 실제 AFPK 시나리오 1개를 추가하고 기존 30개를 유지했다.
- 프로덕션 빌드·포맷 검사 통과. 린트 오류 0개, 기존 `ExtractedViews.tsx`의 TanStack Table `react-hooks/incompatible-library` 경고 1개 유지.
- 전체 검사에서 원본 바이트 동일성·AI 비활성·추가 승인 0회의 발견·원본 근거·기존 팀원 5대상·기본/고급 확인 상태를 검증했다. 실제 AI 호출이나 배포 환경 테스트는 수행하지 않았다.
- 마지막 보수적 이체 분류·확정 상태 차이 안전 보완 후 재현 회귀 27개와 최종 빌드의 실제 AFPK·기존 팀원 Chrome 3개도 재확인했다. 불명확한 이체를 저축으로 채택하거나 서로 다른 상태의 단위 표현을 자동 병합하지 않는다.

최종 로컬 커밋은 완료 보고에 기록한다. 복구 시 현재 작업을 보존한 뒤 `git switch -c restore/afpk-baseline baseline-before-afpk-20261113`로 수정 전 브랜치를 만들어 비교할 수 있다. 강제 reset·push는 사용하지 않는다.
