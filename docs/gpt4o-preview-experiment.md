422의 상세 코드는 `UNSUPPORTED_LITERAL`이며 원문에 없는 숫자·조건을 허용하도록 검증을 완화하지 않았다. 어떤 필드가 불일치했는지와 원시 모델 출력은 서버에서 반환하거나 로그에 남기지 않아 원인을 단정할 수 없다.

유형·숫자·출처 검사 후 **채택 가능한 후보는 1/3유형(33.3%)**이다. 그러나 지원금 대상명도 잘못되어 대상 식별까지 포함한 완전한 구조화 성공은 **0/3**이다. 정상 대조는 1/1건 경고 없음이다. 표본이 매우 작고 각 최종 케이스를 한 번만 실행했으므로 일반 검출률·재현성으로 해석하지 않는다. 관계 후보의 수용과 최종 오류 판정은 서로 다르다.

최종 4요청의 비용 합계는 $0.00053010이다. 첫 평가에서는 중복 배정·지원금이 400으로 거부되어 사용량을 반환하지 않았고 ETF·정상 대조는 각각 $0.00005085/$0.00004725였다. 따라서 8요청 중 **측정 가능한 비용 합계는 $0.00062820**, 두 요청의 비용은 미측정이다. 청구서의 실제 총액을 측정했다고 주장하지 않는다. 캐시 할인 없이 입력 $0.15/백만 토큰·출력 $0.60/백만 토큰으로 추정했다.

## 호환성 수정과 모의 테스트

- 비추론 모델에 맞춰 `reasoning` 옵션을 제거했다. 기존 strict Structured Outputs 형식을 유지했다.
- 초기 스키마에서 자유 문자열이던 action을 기존 엔진의 유지·중단·시작·증액·감액·null로 제한했다. 배정/선반영 동사는 null로 요구한다.
- 모델 응답의 원문 검증 실패는 422 AI_OUTPUT_REJECTED와 허용된 진단 코드만 반환한다. 숫자·원문·키를 오류 로그에 기록하지 않는다. 거부된 응답도 비용·시간 메타데이터는 보존한다.
- 서버 모델·요율·스키마·동의·실패 복구 모의 테스트는 실제 모델 품질 평가와 구분한다. 빌드·린트·포맷을 통과했고 기존 TanStack Table 경고 1건이 있다.

공식 [모델 문서](https://developers.openai.com/api/docs/models/gpt-4o-mini)와 [Structured Outputs 규격](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)을 확인했다. 이 모델은 공식 문서상 deprecated이지만 이번에는 사용자 요청 모델을 유지했다.

## 기존 엔진 연결과 채택 결정

성공한 지원금 응답은 sourceId=s0의 원문 전체를 인용했고 127/만 원을 유지했다. 기존 importProposal은 이를 금액이 있는 **미확인 지원금 행**으로 가져올 수 있지만 승인·수령·반영처·대상 식별은 사람이 보완해야 한다. 이번 호출로 ALLOC·PLAN 최종 오류 판정이 성공했다고 볼 수 없다. 원본 대조에서 거부된 두 유형은 엔진 입력으로 채택하지 않는다.

API 연결·키·Structured Outputs 호환성은 실제 응답으로 확인했다. 기존 403 모델 접근 오류는 이 모델에서 재현되지 않았다. 그러나 구조화 품질은 불충분하므로 **Production AI 비활성을 유지한다**. 기본 규칙 검사는 그대로 사용하고, 실제 팀원 문서 AI 평가와 추가 모델/프롬프트 개선은 별도 작업으로 판단한다. 사용자 조작 감소 효과도 아직 입증하지 못했다.
