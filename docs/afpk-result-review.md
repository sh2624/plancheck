# AFPK 결과 오연결·파생 기록 최종 점검

## 실제 원본에서 확인한 내용

- 총자산 23,000만 원과 입출금통장 800만 원을 직접 비교하는 CROSS 결과는 없다. CALC_ASSETS의 원본 항목 배열은 ‘총자산, 입출금통장, 예금, ETF, 연금저축, 보증금’ 순서다. 이전 화면이 앞의 네 항목만 기본 금액 영역에 표시해 구성 항목을 비교값으로 오해할 수 있었다. 실제 엔진은 다섯 자산 전체 20,000만 원을 합산했고 차이는 3,000만 원이었다. 23,000−800 같은 계산은 수행하지 않았다.
- 이 화면은 기재 총자산과 ‘구성 항목 5개 합계’만 비교하도록 수정했다. 개별 계정·원문·위치·합계식은 판단 근거에서 유지한다. 다른 CALC 결과도 목표값과 전체 재계산값을 보여준다.
- Word 내부 구성은 800 + 1,200 + 2,200 + 800 + 15,000 = 20,000만 원이다. 총자산 기재 23,000만 원과 3,000만 원 차이가 있다. 이는 Excel 총자산 20,000만 원과 Word 23,000만 원의 문서 간 비교와 별도의 검증 근거다. 두 근거를 삭제하거나 같은 규칙으로 바꾸지 않고 한 대표 발견 아래 보존했다.
- 양 문서 총부채는 8,000만 원이다. Excel 순자산은 20,000−8,000 = 12,000만 원, Word 요약표는 23,000−8,000 = 15,000만 원이다. 원본 ID로 연결된 두 NET 계산과 부채 비교가 모두 일치하므로 문서 간 순자산 3,000만 원 차이는 자산 차이에서 파생된다. Word의 순자산 뺄셈 자체를 별도 계산 오류로 만들지 않는다.
- 자동 연결에서 제외한 10개 관계(입출금통장↔정기예금, 근로소득↔기타소득·총유입 등)는 모두 상세 분석 기록이다. 실제 비교 엔진에 넣지 않아 actual·expected·difference가 없으며, 우선 검토·추가 확인에 표시하지 않는다.

## 묶음 기준과 안전 조건

같은 금액 차이만으로 합치지 않는다. 총자산/총자산 합계 같은 한정된 합계 별칭의 반복 기재만 공통 원본·동일 값·단위·각 원본의 기준 조건을 대조해 묶는다. ‘과세 대상 총자산’ 같은 다른 범위 명칭은 별도로 유지한다.

자산과 순자산은 다음 증거가 모두 있을 때만 파생 관계로 묶는다.

1. 문서 간 자산·순자산 비교의 차이가 같은 방향과 금액이다.
2. 각각의 동일 파일·원본 ID에 연결된 NET 계산이 존재한다.
3. 선택된 총자산·총부채와 순자산의 실제 숫자로 뺄셈이 성립한다.
4. 두 총부채의 동일 원본 비교가 수치 일치이고 명시적 기준 충돌이 없다.
5. 계산 입력의 기준일·기간·시나리오·확정 상태가 각 문서 내부에서 같고, 연결 가능한 원인 묶음이 하나다.

증거 누락·원본 ID 불일치·파일·기간·기준일·시나리오 차이·부채 차이·사용자의 모름 답변은 묶지 않는다. 같은 원본의 CALC·CROSS도 명시적 비교 조건 충돌이 있으면 묶지 않는다. 사용자 응답이나 원본이 바뀌면 현재 결과로 묶음을 다시 계산한다.

이는 원문 수치와 산식의 산술적 연결을 설명하는 표시 묶음이다. 작성 기준이 미기재된 문서에 같은 기준일을 채우거나 실제 오류 원인을 최종 승인하는 기능이 아니다. 구성원별 검증 상태·원본·사용자 응답을 바꾸지 않는다. 대표 발견을 승인해도 파생 근거의 미확인 조건까지 자동 승인하지 않는다.

우선 발견은 자산 관련 3,000만 원 차이와 연간 순현금흐름 120만 원 차이다. 새 계산 오류를 만들거나 유효한 결과를 통과로 바꾸지 않았다. 실제 AFPK에서 잘못된 직접 비교는 재현되지 않았으며, 이번 수정의 핵심은 구성 항목 표시의 오해와 동일 산식의 파생 결과 반복이다.

## 검증과 남은 한계

검증 엔진·파서·정규화·승인 상태 모델은 수정하지 않았다. 변경은 표시 묶음과 결과 카드 요약이며, 회귀 테스트와 이 보고서를 추가했다.

- 임의 금액의 실제 추천·검증 결과로 인과 관계 및 8가지 거절 조건을 검사한다. 입력 객체와 승인 상태가 변하지 않는지 검사한다.
- 실제 AFPK 두 파일에서 2개 대표 발견, 10개 제외 관계의 비노출, 전체 구성원 보존, Word 내부 자산 합계의 상세 접근을 검사한다.
- Chrome에서는 검사 시작 후 자산·연간 차이를 확인하고 파생 근거를 열어 순자산·자산 구성 셀과 문단을 확인한다. 총자산과 입출금통장이 기본 비교값에 함께 표시되지 않는지 확인한다.
- 기존 팀원 파일의 잉여금 2만 원·총자산 20만 원·예금 배정·조건부 금액·ETF 계획 다섯 대상과 상태 초기화는 기존 전체 회귀에 포함한다.

산식이나 동일 원본 연결이 부족하면 차이가 같아도 별도 결과로 둔다. 범용 자연어 원인 추론은 하지 않는다. ‘묶음’은 독립적인 재무 사실을 삭제하는 것이 아니며, 실제 잘못된 금액·작성 기준의 최종 판단은 기존 확인 조건에 따른다.

최종 실행 결과:

- 전체 Vitest 47파일 385개 통과(기존 375개 유지, 표시·인과 회귀 10개 추가).
- Chrome E2E 31개 통과, AI 비활성화 관련 모의 API 테스트 1개 건너뜀. 기존 팀원 원본의 자산 근거 수는 순자산 파생 근거 추가 보존으로 1→2가 되어, 원본 위치·자산/순자산 내용까지 검사하도록 기대값을 보완한 뒤 전체 Chrome 검사를 재통과했다.
- 프로덕션 빌드·포맷 검사 통과. 린트 오류 0개, 기존 TanStack Table `react-hooks/incompatible-library` 경고 1개 유지.
- 원본 파일은 변경·전송·커밋하지 않았고 push·배포도 하지 않았다. 최종 로컬 커밋 해시는 완료 보고에 기록한다.
