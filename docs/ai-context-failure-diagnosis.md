# AI 문맥 실패 진단 — 2026-11-12

## 결론

정상적인 단위 환산을 거부하던 문제와 어댑터의 데이터 손실은 개선했다. 그러나 **실제 검수 흐름에서 기존 규칙 방식보다 나아졌다고 결론 내릴 수 없다**. 최종 양성 6건 중 올바른 관계·금액·출처를 함께 수용한 것은 4건이고, 정상 대조 2건 중 1건에는 불필요한 미확인 후보가 남았다. 자산/목표 ID·제안/실행·승인/수령·기간을 자동 확정하지 않아 완성된 엔진 판정은 0건이다. Production AI 비활성을 유지한다.

API 연결, 관계 추출, 출처 검증, 엔진 입력 구성, 사용자 확인 후 최종 판정은 다른 지표다. 아래 수치를 합쳐 검출 성공으로 표시하지 않는다.

## 실험 자료

- 기준은 `baseline-ai-diagnosis-20261112` / `d710037`이다. 이전 실험에서 거부된 원시 JSON은 남아 있지 않으므로 당시 실패 필드를 소급 확인했다고 주장하지 않는다. 같은 설정으로 **새 기준 실험**을 했다.
- 기본 3유형+정상 1건, 별도 표현·상품명·금액·단위를 사용한 변형 3유형+정상 1건을 기준/1차 수정/최종 수정에 각각 한 번씩 실행했다. 총 **24회 실제 OpenAI 호출**이며 자동 재시도는 없다.
- gpt-4o-mini, Responses, strict Structured Outputs, 출력 1,600토큰, 상류 타임아웃 15초를 유지했다. 기본 샘플링으로 출력이 변동한다. 단계별 지침·스키마는 개선했으며 모델 간 비교 실험은 아니다.
- [합성 입력](../tests/ai-diagnostic-cases.json)과 [증거 JSON](ai-diagnostic-evidence.json)에 실제 지침·스키마·입력·원시 응답·거부 경로·정규화된 엔진 입력을 보존했다. 기대값은 모델에 보내지 않았다. 모두 가상 자료이며 실제 팀원 문서·개인정보·API 키는 포함하지 않았다.
- 임시 Preview는 고정 합성 caseId만 받았고 일반 문서 입력을 받지 않았다. 해당 실험본에서만 원시 JSON을 수집했으며 로그에 남기지 않았다. 일반 앱 API에는 원시 응답 반환·저장을 추가하지 않았다.

## 세 사례의 실패 위치

### 중복 배정

실제 입력은 s0의 ‘가상 예금 보유액 730만 원’, s1의 ‘2027-01-01 비상자금 730만 원 배정’, s2의 ‘같은 날짜 의료비 280만 원 배정’이다. 세 문장을 함께 전송했다.

기준 모델은 자산과 두 배정을 맞게 연결했지만 `number: "7300000", unit: "원"`, `"2800000"/"원"`으로 환산했다. 기존 검증기는 `proposals[0].evidence[0].number`가 인용문에 그대로 없다는 이유로 UNSUPPORTED_LITERAL을 반환했다. **환산은 맞고 검증기가 올바른 표기 차이를 거부한 경우**다. 동일 JSON을 새 검증기에 오프라인 재생하면 통과한다. 새 AI 호출의 성공과 이 재생 실험은 구분했다.

새 검증기는 숫자·단위를 쌍으로 묶어 유리수로 정확히 비교한 뒤 원문 730/만 원, 280/만 원으로 복원한다. 차이가 있으면 통과시키지 않는다. 최종 호출도 두 배정을 수용했다.

어댑터는 여전히 관계 하나를 미확인 배정 행 하나로 가져온다. assetId·goalId·배정액·기간이 비어 ALLOC_CAPACITY는 검증 불가다. 복수 목표/배정 행 구성을 완성하는 것은 현재 스키마·어댑터의 한계다. 근거 없는 ID와 관계를 만들지 않았다.

### 조건부 지원금

입력은 ‘가상 지원금 **127만 원**, 미승인·미수령, 현재 확정 자산 포함’ 한 문장이다. 이번 새 기준 응답은 대상명·127/만 원을 맞게 반환했다. 과거 실험에서 대상명을 ‘127만 원’으로 추출한 출력과 동일하다고 취급하지 않는다.

최종 재호출은 관계와 대상은 맞았으나 `number: "127", unit: "원"`을 반환했다. 원문 1,270,000원과 모델 127원은 다르므로 UNSUPPORTED_AMOUNT_UNIT으로 거부했다. **모델의 실제 단위 오류이며 검증기의 오거부가 아니다.** 원문 단위로 억지 보정하지 않았다.

변형은 미승인·미입금 문장과 현재 자산 합산 문장을 나누고 960,000원/96만원으로 표현했다. 최종 모델은 두 문장과 같은 주거지원 보조금을 연결했다. 과거 어댑터는 근거가 둘 이상이면 금액을 버렸다. 이제 같은 명시적 대상의 모든 금액이 정확히 같을 때만 원본 금액 하나를 보존한다. 값이 다르면 선택하지 않는다. approval·received·destination·confirmed는 미확인으로 남아 PLAN_CONDITIONAL은 검증 불가다.

### ETF 행동 충돌

입력은 s0의 ‘2027년 가상 ETF 월 17만 원 중단 제안’과 s1의 ‘같은 상품·연도·금액 유지 실행’이다. 두 문장을 함께 전달했다.

기준 원시 JSON은 관계는 찾았지만 대상명에 연도를 섞었고 number에 `"17만 원"`, unit과 timing에 실제 JSON null 대신 문자열 `"null"`을 넣었다. 첫 거부 필드는 unit이며 뒤의 숫자 형식도 잘못됐다. 이는 **공백 차이가 아니라 역할·자료형이 섞인 구조화 실패**다.

스키마에 숫자 패턴·단위 열거값·nullable 대상·역할 설명을 추가했다. 그래도 최종 모델은 17/원을 반환했다. 원문 170,000원과 달라 거부했다. 변형 분산채권 펀드는 230,000원/23만원과 두 문장의 중단·유지를 정확히 추출했다.

기존 어댑터는 검증된 action·amount도 버렸다. 이제 이 값은 보존하지만 targetId·side·기간·시나리오·사용자 확인은 자동 확정하지 않는다. PLAN_CONFLICT는 필요한 연결을 안내하는 상태로 남는다.

## 출처 검증의 구분

- 공백 차이만 허용하고 원문 안의 실제 연속 구간으로 복원한다. 재작성·동의어·없는 대상명을 유사도만으로 승인하지 않는다.
- 쉼표와 원/만 원/억 원 차이는 정확히 같은 양일 때만 정규화한다. 화폐·금리·기간은 차원을 구분하고 BigInt 유리수 비교로 반올림 허용오차를 만들지 않는다.
- ‘원’, ‘만원’, ‘127만 원’, 순수 숫자·행동은 대상명이 아니다. 없는 대상은 null로 두고 certainty를 unknown으로 낮춘다. AI certainty는 사용자 confirmed와 별개다.
- 변형 배정에서 모델은 ‘같은 기간’ 문장에 앞 문장의 ISO 기간을 복사했다. 문서 전체에는 있어 순수한 날조는 아니지만 해당 quote에는 없다. 같은 제안의 다른 증거에 실제 기간이 있고 현재 문장에 명시적인 참조가 있을 때만 **현재 timing을 null로 보류**하고 이유를 남긴다. 날짜를 자동 채우지 않는다. 어느 근거에도 없는 날짜는 거부한다.
- 다른 명시적 대상의 행동 연결은 RELATION_TARGET_MISMATCH로 차단한다. 그러나 한쪽 대상이 null인 정상 대조에서는 잘못된 미확인 관계 제안이 남았다. 이를 숨기거나 통과 판정으로 바꾸지 않았다.
- 거부 진단은 path·고정 code·category만 반환하며 숫자-단위 결합은 relatedFields로 두 필드를 표시한다. 값·키는 오류 메시지나 로그에 넣지 않는다. 실제 응답 당시 진단과 최종 코드로 재생한 진단은 JSON에서 분리했다. 각 검증은 첫 실패에서 중단하므로 후속 필드의 모든 오류를 자동 수집했다고 주장하지 않는다.

## 엔진 연결과 기존 방식 비교

engineInput/engineResults는 실제 모델 출력을 기존 importProposal·validatePlanning에 **오프라인 재생한 순수 함수 실행**이다. 앱에서 자동 가져오기나 사용자 승인을 실행하지 않았다. 엔진 함수 호출과 필수 연결이 완성된 판정은 다르다.

기존 extractPlanning도 같은 문장의 지원금/중단·유지 후보를 찾았다. 변형 행동에서는 두 개 중 한 행동만 찾았다. AI는 일부 문맥을 더 잘 묶었지만 필수 ID·목표·기간·상태를 완성하지 못했다. 비교 입력은 문맥 조각이므로 XLSX·DOCX 업로드 전체의 규칙 검출률과 동등하게 해석하지 않는다. ALLOC의 복수 배정 구성, PLAN의 승인·수령·반영처·대상 매핑이 병목이며 이는 상위 모델만 바꿔 해결되지 않는다. 접근이 확인된 gpt-4o-mini만 사용했고 상위 모델 비교나 사용자 조작 감소 측정은 하지 않았다.

## 검증과 운영 결정

전체 230개 테스트, Chrome 기본 흐름 17개, 별도 AI 활성화 빌드의 모의 API Chrome 흐름 1개가 통과했다. 실제 API 호출 24건과 모의 응답 Chrome 테스트는 별개의 증거다. 빌드·린트·포맷을 통과했으며 기존 TanStack Table 경고 1건이 있다. CALC·CROSS·기존 파서·계획 검증 엔진 파일은 수정하지 않았다.

변경은 단계별 로컬 커밋으로 분리하고 push·Production 활성화는 하지 않는다. 임시 원시 JSON 수집 Preview는 실험 후 삭제한다. **개선된 것은 표기 대조와 데이터 보존이며 실사용 정확도·조작 수의 우위는 확인되지 않았다. 제출 버전은 기존 규칙 검사를 우선 사용한다.**

## 재현

`node scripts/prepare-ai-diagnostic.mjs`는 키 없이 고정 합성 진단 프로젝트를 .cache에 준비한다. 기존 Vercel 프로젝트의 보호된 Preview에만 별도 배포해 수집한다. 입력은 caseId와 baseline/candidate뿐이며 기대값·키는 모델에 보내지 않는다. 원시 응답은 `.cache/diagnostic-{mode}-{caseId}.json`에 보관했다. `node scripts/summarize-ai-diagnostic.mjs`는 저장 응답을 오프라인 재생하고 보고서를 생성하며 API를 자동 호출하지 않는다.

Structured Outputs의 형식 보장은 의미 정확성 보장이 아니므로 [공식 규격](https://developers.openai.com/api/docs/guides/structured-outputs)의 null 경로와 별도 출처 검증을 유지했다.
